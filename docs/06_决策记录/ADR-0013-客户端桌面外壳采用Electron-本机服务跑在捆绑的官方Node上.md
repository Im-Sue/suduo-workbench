# ADR-0013: 客户端桌面外壳采用 Electron，本机服务跑在捆绑的官方 Node 上

> **状态**：accepted（用户 2026-10-06：「仍用Electron。其他的我都能接受，你现在开始从d0全权推进」）｜**拍板人**：用户（外壳形态、首版不签名），Claude（本机服务的运行时，用户已接受）

---

## 一、背景

客户端要从「源码运行」改为 Mac、Windows 上双击安装的桌面应用（[需求](../02_需求设计/客户端桌面应用安装包-需求.md)）。要定两件事：

1. 用什么做桌面外壳；
2. 本机服务（Fastify + better-sqlite3）在安装包里跑在哪个 Node 上。

相关原话：2026-10-02「客户端不要去改electron，我们后面再沟通打包的问题吧」，当时说的是源码运行阶段。2026-10-06 用户听完 Electron 与 Tauri 的对比后说「开始梳理实施方案和需求方向，首版不签名，作为试用版发布」。

体积更正（Electron 方案约 280–300 MB，比 Tauri 多约 120 MB）告知用户后，用户回复「仍用Electron。其他的我都能接受，你现在开始从d0全权推进」（2026-10-06）。

约束：
- 界面的全部验收（gate-c、视觉基线、无障碍检查）都在 Chromium 上完成。
- 房间共享 Agent 要求所有者本机的服务一直在跑。
- 全仓只用 TypeScript。
- 安装包体积的大头是 Codex（单平台压缩后约 130 MB）。
- better-sqlite3 12.11.1 的 Electron 预编译包只到 ABI 146（Electron 42），当前最新的 Electron 44 是 ABI 149；13.x 的发布不再附带预编译包。

---

## 二、决策

1. 桌面外壳用 **Electron**（以 44.x 起步）。外壳只负责拉起本机服务、窗口、托盘、通知、更新和开机自启，不承载业务逻辑。
2. 本机服务用**安装包里捆绑的官方 Node 24** 作为子进程运行，与源码运行同一份代码、同一个 SQLite 预编译包。不用 Electron 内置的 Node。
3. 首版不做代码签名：Mac 用临时签名，Windows 不签名，作为试用版发布。签名和公证单独作为后续一片。

---

## 三、否决的方案

| 方案 | 否决理由 |
|---|---|
| Tauri | Mac 上用系统 WebKit，与 Chromium 上的验收不一致；前端的通知、下载和外链要改；引入 Rust。体积上约少 120 MB，但不足以抵消这些 |
| 启动器 + 浏览器（旧 Windows 安装器的思路） | 没有常驻，关浏览器后服务会空闲退出，共享 Agent 掉线；Mac 上还要从零写外壳 |
| 本机服务跑在 Electron 内置的 Node 上（utilityProcess） | 能省约 35 MB，但 SQLite 模块要按 Electron 版本在每台构建机上现场编译，每次升级 Electron 都会牵动本机服务；而且内置的 Node 不是测试所用的官方构建 |

---

## 四、影响

- 安装包下载约 280–300 MB，安装后约 700 MB（实测为准）。
- 要定期跟进 Electron 的维护周期（只维护最近三个大版本）。升级只影响外壳，本机服务不受牵连。
- Mac 未签名期间，首次打开要用户手动放行，也不能一键更新；可能还需要手动去掉隔离标记（待实测）。
- 旧的 Windows NSIS 安装器（`client/scripts/dist-win/`）退役。
