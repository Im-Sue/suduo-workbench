# ADR-0009: 房间共享 Agent 的数据边界

> 一个决策一篇，记下「为什么这么定」，防止以后反复扯 / 误改
>
> **状态**：accepted ｜ **拍板人**：用户（2026-09-30：「团队的 ai 也是团队本身提供给成员的，所以不需要什么约束。在业务层或者团队管理层做好管理、约束即可」；执行过程完整展示、不放虚拟机、只问答与规划，见需求第三节）

---

## 一、背景

V2 的数据边界一句话是「**共享的是需求，私有的是代码和对话**」（项目总览）。[项目聊天房间与共享 Agent](../02_需求设计/v2-项目聊天房间与共享Agent-需求.md) 让成员把自己的 Codex 共享进房间：别人 @ 它，它在所有者电脑上、在项目代码目录里只读分析，回答**连同完整执行过程**（查看了哪些文件、运行了哪些命令及输出）挂在房间话题下，全员可见。

这改变了原边界：执行过程里有代码片段与命令输出，会进入远程需求服务的数据库；Codex 只读沙箱可读整盘，房间里的人可以借所有者的 Agent 读所有者电脑上的文件。用户已明确不加系统约束，需要把边界写清楚，免得以后有人当成缺陷「修」掉，或在别处误以为代码从不出本机。

## 二、决策

1. **执行只在所有者本机**：不在服务端跑 Codex，不放虚拟机（执行器做成可替换，放开改代码时再评估）。
2. **所有者主动共享才可见**：按房间逐个开启，可选时长，随时关闭；关闭、到期或本机下线后立即不可被 @，正在执行的任务停止。
3. **共享期间，回答与完整执行过程归房间**：存远程需求服务（`agent_runs.events`、话题回复消息），房间全员可见，与需求评论一样是团队数据。单条命令输出截 4000 字、整段过程截 1.5MB，只为控制体积，不是脱敏。只上传**这次任务那一回合**的事件（按回合 ID 认）；房间任务会话在所有者的会话页只读，所有者私下的对话不会混进来。
4. **能力只问答与规划**：Codex 只读沙箱 + 可联网 + 不弹审批；房间 Agent 不挂写笔记、发评论、发布确认版这类写工具。
   - **所有者配置的 MCP server 与连接器在房间任务线程里一律关掉**（建线程与续接都带配置覆盖，按生效配置逐个 `enabled = false`）：它们不受只读沙箱限制，不关的话房间成员可以借 Agent 免审批调用所有者的外部写操作。读不到 Codex 配置时不建线程、这次任务失败——确认不了已关掉，按 ADR-0004「不可逆对外副作用」红线宁可拒绝。插件自带的工具不在 SuDuo 管理范围内（SuDuo 的 Codex 目录默认不装插件）。
   - **唯一会写所有者磁盘的是 SuDuo 本机自己**：房间工具查看房间文件、需求附件、产物时，较大的文件由 SuDuo（不是 Codex）存进项目下的 `.suduo/`（整目录 `.gitignore`），供 Codex 只读读取；Codex 本身不修改任何文件。
5. **不做额外约束**：不限制读取范围、不屏蔽敏感文件、不设发出前过目、不设额度（用户原话）。由团队管理层负责。
6. **私有部分不变**：所有者自己的本机会话、结论笔记、房间任务以外的代码仍只在本机。

边界的新表述：**共享的是需求和房间讨论（含被共享 Agent 的回答与执行过程）；私有的是代码仓库和个人会话。**

## 三、否决的方案

| 方案 | 为什么没选 |
|------|------------|
| 只把回答发到房间，执行过程只留所有者本机 | 用户决定完整展示；既然不做约束，没有理由只给摘要，复用会话时间线实现也更简单 |
| 默认只读项目目录、屏蔽 `~/.ssh` 等敏感路径 | 用户明确「不需要什么约束」；Codex 只读沙箱的读取范围是整盘，要限制得改权限配置文件，留到放开改代码时一起评估 |
| 放进虚拟机执行 | 每台机器装虚拟机运行时与镜像，没有本机开发环境与凭据；收益在「内网、团队提供 AI、只问答」前提下很小 |

## 四、影响

- **好处**：PM 等没有代码的成员可以直接问到代码层面的事，回答与依据全员可见，不再口口相传。
- **代价 / 风险**：所有者电脑上任何其能读的文件，都可能被房间成员借 Agent 读出并显示在房间里——靠「主动共享、随时关闭」与团队管理控制；执行过程体积增大服务器存储。
- **受影响**：`docs/00_项目总览.md`（数据边界一句话）、系统架构的数据归属表、远程需求服务的存储与备份范围（多了房间消息、文件、执行过程）。
