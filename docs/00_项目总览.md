# SuDuo 项目总览

> 给人和 AI 快速摸清项目全貌 —— 回来先读这一篇 ｜ 最后更新: 2026-10-02（按本地 `main` 校对）｜ 常青文档(跟随整个系统,无 status)

---

## 一句话

面向内网团队的**需求协作 + 本机 Codex 开发工作台**：远程服务统一管理项目与需求，每个人在自己电脑上打开 SuDuo，从需求一键拉起本机 Codex CLI 会话，在本地工作目录里干活。

**定位是 AI 协作平台**：人永远在回路里，且比系统掌握更多上下文。系统负责让"对不齐"可发现、可表达、可恢复；冲突由人仲裁，不由系统拒绝（[ADR-0004](06_决策记录/ADR-0004-人机协作系统的一致性边界.md)）。

用一句话概括数据边界：**共享的是需求和房间讨论，私有的是代码仓库和个人会话。** 成员主动把自己的 Codex 共享进房间时，它在房间里的回答与执行过程归房间、全员可见；执行仍只在所有者本机（[ADR-0009](06_决策记录/ADR-0009-房间共享Agent的数据边界.md)）。

## 当前版本 / 方向

- **当前版本**：`0.8.0`（`client/package.json` 与 `cloud/package.json`；新增英文界面，变更见 [CHANGELOG](../CHANGELOG.zh-CN.md)；0.7.0 是首个公开版本）
- **仓库**：公开研发仓库 [Im-Sue/suduo-workbench](https://github.com/Im-Sue/suduo-workbench)（2026-10-02 起，以清理后的快照首发）；私有仓库 Im-Sue/suduo 只作历史存档，不再改动
- **形态**：**V2 —— 远程共享需求服务 + 本机 BFF/UI + 本机 Codex CLI 三段分离**
- **代码组织**：按部署的两端分成 `client/`（装在用户电脑上：前端 + 客户端后端）与 `cloud/`（部署在内网服务器：云端服务端），各是独立的 pnpm 工作区，进到对应目录安装、构建、测试、运行（[ADR-0010](06_决策记录/ADR-0010-仓库按客户端云端两端拆分-品牌更名SuDuo.md)）
- **入口文档**：[SuDuo V2 系统架构](01_架构设计/v2-系统架构.md)

V2 是唯一形态：浏览器打开 `/` 即 V2 工作台。旧 M1/TAPD 线（含 `/legacy` 入口、`work_items`/`tapd_*` 表、`sessions.task_id`）已由 T4 **整体删除**，不是隐藏或停用。

**V2 不是什么**：不在服务端跑 Codex、不让浏览器直连远程服务或附件目录、不做 TAPD 兼容/双写/旧数据迁移、不做密码找回/角色权限/组织租户、不做状态机守卫、**不做并发/一致性守卫**（检测并告知，冲突由人仲裁，见 ADR-0004）。

## 业务线

V2 是 **3 条业务线 + 1 条横切支撑线**：

```
L1 共享需求协作 ──┐
                  ├──→ L3 需求→会话桥接（V2 的独有价值）
L2 本机 AI 开发 ──┘
          L4 平台 · 安全 · 发行（横切支撑）
```

| 线 | 承载模块 | 数据归属 | 内容 |
|---|---|---|---|
| **L1 共享需求协作** | `cloud/server` `/v2` | 远程 PostgreSQL + 受控附件卷 | 账号、项目、需求、评论、附件、审计、SSE；**项目 / 需求聊天房间**（消息、文件、视频、话题、共享 Agent 的任务与结果）。可独立部署与验收 |
| **L2 本机 AI 开发会话** | `client/server` `/api/v1` + `client/web` 会话运行时 | 本机 SQLite + 用户工作目录 | 会话、消息、审批、工具调用、文件、Git 检查点、Skill、Composer。M1 期已有能力，V2 只换需求来源 |
| **L3 需求→会话桥接** | `client/server` `/api/v2` + 两张 `v2_*` 表 + 会话工具 | 本机 | **V2 新增，是连接 L1/L2 的唯一通道**：项目→本机目录映射、映射预检与原地续办、开工版本登记、需求卡 + `suduo_*` 需求工具（ADR-0008） |
| **L4 平台 · 安全 · 发行** | LoopbackGuard、迁移守卫、部署与安装资产 | 横切 | 本机访问边界、token 治理、Docker/compose、NSIS/systemd、回滚策略 |

没有 L3，L1 只是普通需求看板、L2 只是普通 AI 编码工具——L3 才是 V2 立项的理由。

## 核心模块

两个独立的 pnpm 工作区，共六个包。依赖只能从客户端指向云端：客户端经 `link:` 引用 `cloud/contracts`，云端不依赖客户端任何东西。

| 模块 | 路径（包名） | 状态 | 说明 |
|------|------|------|------|
| 云端服务端（远程需求服务） | `cloud/server`（`@suduo/cloud-server`） | 在用 | **V2 需求数据唯一权威真相源**。Fastify + PostgreSQL，`/v2` REST + SSE，附件落服务器受控持久卷。默认监听 `0.0.0.0` |
| 客户端后端（本机 app-server） | `client/server`（`@suduo/client-server`） | 在用 | 本机 BFF + 会话运行时宿主。`/api/v2` 代理远程服务，给需求会话挂需求工具，`/api/v1` 跑 Codex 会话，同时托管前端产物。**强制只听 `127.0.0.1`** |
| 前端 SPA | `client/web`（`@suduo/web`） | 在用 | React 19 + Vite + Tailwind v4 + TanStack Router / Query。侧栏外壳下五个区域：我的工作 `/my`、需求 `/p/:项目/requirements`、会话 `/sessions`、概览 `/p/:项目/overview`、设置 `/settings/:分组`；旧路径全部重定向（见 [client/web 架构](01_架构设计/client-web-架构.md)） |
| 云端 API 契约 | `cloud/contracts`（`@suduo/cloud-contracts`） | 在用 | 零依赖类型/常量库：账号、项目、需求、评论、附件、活动、统计、房间。云端与客户端共用 |
| 客户端契约 | `client/contracts`（`@suduo/client-contracts`） | 在用 | 零依赖类型/常量库：会话运行时、事件、配置、会话工具，以及只在本机 BFF 与前端之间的 local / workbench / attachment-preview |
| Codex 协议基线 | `client/codex-protocol`（`@suduo/codex-protocol`） | 在用 | Codex CLI JSON-RPC schema 版本锁与漂移哨兵。不被任何代码 import，只在校验链路上跑 |

数据归属速查：

```
远程 PostgreSQL + 附件卷  →  项目 / 需求 / 评论 / 附件 / 审计；房间 / 消息 / 房间文件 / Agent 共享与任务结果（共享真相）
本机 SQLite               →  会话（含房间任务会话）/ 审批 / 事件账本 + v2_* 映射与开工登记（私有）
本机工作目录              →  用户源码，Codex 在此运行；.suduo/ 放 SuDuo 本机文件（整体不进 git）
```

新旧路径与名称对照（2026-10-02 起，ADR-0010；旧文档与旧提交里的写法按此对应）：

| 旧 | 新 |
|---|---|
| `apps/web` | `client/web` |
| `apps/server`（`@zjwork/server`） | `client/server`（`@suduo/client-server`） |
| `apps/requirements-service`（`@zjwork/requirements-service`） | `cloud/server`（`@suduo/cloud-server`） |
| `packages/contracts` 根导出（`@zjwork/contracts`） | `client/contracts`（`@suduo/client-contracts`） |
| `packages/contracts` 的 `requirements-v2`（`@zjwork/contracts/requirements-v2`） | `cloud/contracts`（`@suduo/cloud-contracts`）；其中 local / workbench / attachment-preview 归 `client/contracts` |
| `packages/codex-protocol` | `client/codex-protocol` |
| `scripts/dev-postgres.sh` | `cloud/scripts/dev-postgres.sh` |
| `scripts/` 其余 | `client/scripts/` |
| 品牌 ZJWork / `zjwork` / `ZJWORK_*` / `.zjwork/` | SuDuo / `suduo` / `SUDUO_*` / `.suduo/` |

## 项目约定

- **协作分工**：所有需求的规划与实施由 Claude 独立完成，不派工或咨询 Codex（[ADR-0005](06_决策记录/ADR-0005-停用CCB与Codex协作-需求规划与实施由Claude独立执行.md)）。详见 `CLAUDE.md`。
- **真相源**：`docs/` 人读文档（含 frontmatter 状态，由 Claude 手动维护）。
- **状态只属实体**：需求 / 任务 / ADR 有 `status`，其余文档无生命周期状态。
- **目录约定**：见下方「文档目录」。文件名默认 `<模块/主题>-<文档类型>.md`（不加日期前缀）；模块规格为 `<部分>-<模块>模块规格.md`；ADR 为 `ADR-NNNN-<slug>.md`。
- **常用命令**：
  ```bash
  # 两端各自执行（进到 client/ 或 cloud/）
  pnpm install / build / typecheck / lint / test   # 该端全部包递归；客户端构建会顺带编译 cloud/contracts

  # cloud/
  sh scripts/dev-postgres.sh start        # 本机联调用 PostgreSQL

  # cloud/（服务器上）
  sudo ./scripts/suduo-cloud.sh install|upgrade|backup|restore|status   # 私有化部署与运维，见 cloud/DEPLOYMENT.md

  # client/
  pnpm start                              # 源码运行：自检 → 需要时构建 → 启动本机服务并打开浏览器
  pnpm run doctor                         # 环境自检（pnpm doctor 会被 pnpm 自带命令抢走）
  sh scripts/dev-local.sh start|stop|status   # 本机联调栈（云端需求服务 + 本机服务，数据在 SUDUO_DEV_DATA）
  sh scripts/gate-c-vm.sh create|sync|gate-c  # macOS 上用 Lima 虚拟机（Ubuntu + systemd）跑官方 gate-c
  pnpm protocol:diff                      # Codex 协议漂移校验
  pnpm install:m1                         # 本机安装（构建+token+systemd）
  ```
