# SuDuo V2 系统架构

> 一句话定位：用“远程共享需求服务 + 本机 SuDuo 工作台 + 本机 Codex CLI”把团队需求协作和本地开发会话连成闭环。｜最后更新：2026-09-29

## 一、概述与定位

| 项 | 内容 |
|---|---|
| 定位 | 面向内网团队的需求协作与本地 Codex 开发工作台。服务端管理共享需求；开发工作发生在用户自己的电脑。 |
| 架构模式 | 同仓多应用、独立部署：远程需求服务与本地 BFF/UI 分离。 |
| 覆盖范围 | 账号、项目、需求、评论、附件、审计、本地目录映射、从需求创建本机 Codex 会话。 |
| 不覆盖 | 服务端运行 Codex、浏览器直连远程服务或附件磁盘、TAPD 兼容/双写/旧数据迁移、权限后台与密码找回。 |

`cloud/server` 是新增的远程服务，独立 Docker、环境变量、PostgreSQL、服务器受控附件目录和发布流水线；它与现有本机 `client/server` 同仓，但不共享运行时、数据库或部署。附件目录以独立持久卷挂载给远程服务，不与应用镜像层或本机材料缓存共用。

### 代码落地现状（2026-08-15 按分支代码校对）

> ⚠️ **分支归属**：T4/T5 代码在 `ccb/req-suduo-v2-requirements-workbench-001` 分支（worktree `../SU-CCB-req-suduo-v2-requirements-workbench-001`），**尚未合并 `main`**。本节描述的是该分支形态；`main` 上的 `apps/` 仍是清理前形态，读代码请以该分支为准。

**V2 是唯一形态，旧线已物理删除**（不是隐藏或停用）。以下为代码中可验证的事实，不是计划：

| 事实 | 证据 |
|---|---|
| 前端只有一个壳 | `client/web/src/main.tsx` 只渲染 `RequirementsV2App`（DEV 下另有 `/__ui-kit`）；`WorkbenchMode = requirements \| sessions \| settings` |
| `/legacy` 已不存在 | 实测 `/legacy` 响应 md5 与 `/`、随机不存在路径完全相同 = SPA fallback，无独立旧壳 |
| 源码无 TAPD | `apps/*/src`、`packages/*/src`、`scripts` 对 TAPD 的引用数为 **0** |
| BFF 具备完整 V2 路由面 | `client/server` 暴露 18 条 `/api/v2/*` 路径：auth / projects / requirements / comments / attachments / audit / events，以及 `project-mappings`、`workspace-mapping`、`requirements/settings`、项目级与需求级 `sessions` |
| 迁移链已收敛 | 本机 SQLite 仅注册 `[1, 2, 10]`；最终 schema 无 `work_items`、无 `tapd_*`、无 `sessions.task_id` |
| 旧库拒绝启动 | `schema_migrations` 存在 `[1,2,10]` 之外的记录即抛错拒启，提示按 D4 删库重建（已用真实旧库副本实测） |
| 快照版本绑定已落库 | `v2_requirement_session_refs` 以 `requirement_version` 与 `manifest_sha256`（`CHECK length = 64`）固化会话与需求版本的不可变绑定 |
| 本机不复制业务数据 | 本机 SQLite 的 V2 相关表只有 `v2_project_workspace_mappings` 与 `v2_requirement_session_refs` 两张 |
| 部署资产已产出 | `cloud/server/` 下 `Dockerfile`、`compose.yaml`；`cloud/scripts/suduo-cloud.sh` 与 `cloud/DEPLOYMENT*.md` |

**会话运行时不属于旧线**：`/api/v1` 的 sessions / approvals / files / git / skills / settings 是本机开发线（L2）的主体，V2 打开会话时正是复用这套接口。T4-1 已把它从旧壳中抽为独立的 `client/web/src/app/SessionRuntime.tsx`，不再依赖任何旧壳组件。

**尚未完成的部分**：仅剩 T5-3（全新机器闭环验收与发行放行），挂起于外部环境与授权，不涉及代码形态。

## 二、整体结构

```
                    内网远程环境
┌────────────────────────────────────────────────────────────┐
│  requirements-service（cloud/server）          │
│  Fastify API：账号 / 项目 / 需求 / 评论 / 附件 / 审计 / SSE │
│        │                         │                          │
│   PostgreSQL          受控附件目录（独立持久卷）             │
└────────┬────────────────────────┬──────────────────────────┘
         │ Bearer token            │ 仅服务端访问
         │                         │
         ▼                         ▼
┌────────────────────────────────────────────────────────────┐
│ 用户本机                                                    │
│                                                            │
│  浏览器 UI ──同源 localhost──► client/server（本机 BFF）      │
│  需求/会话/设置                       │                    │
│                                       ├─ 保存本机登录态     │
│                                       ├─ 代理 API、文件流、SSE│
│                                       ├─ 项目→本机目录映射  │
│                                       └─ 创建和管理 Codex CLI│
│                                                    │        │
│                         本机工作目录 ◄── Codex CLI 会话 ────┘
└────────────────────────────────────────────────────────────┘
```

浏览器只与 `localhost` 通信。远程服务、服务器附件目录和 Codex CLI 都不暴露给浏览器；现有 `LoopbackGuard` 继续构成本机 BFF 的访问边界。

## 三、运行时职责与数据归属

| 组件 | 职责 | 持有的数据 | 明确不做 |
|---|---|---|---|
| 远程需求服务 | 共享协作 API、账号、项目、需求、评论、附件元数据、审计、需求变更事件 | PostgreSQL 业务数据、服务器受控附件目录中的原始附件 | 不启动、不保存、不转发 Codex 对话 |
| 服务器受控附件目录 | 仅由远程需求服务读写的专用持久卷 | 原始附件字节和暂存文件 | 不提供静态文件服务、不暴露主机路径、不接受浏览器或 BFF 的磁盘访问 |
| 本机 `client/server` | 本机 BFF、远程 token 持有、远程 API/文件/SSE 代理、本机目录映射、Codex 生命周期 | V2 本机配置、token、本机会话和材料缓存 | 不成为共享需求的真相源 |
| 本机 `client/web` | Symphony 风格的需求/会话/设置交互 | 短暂 UI 状态 | 不保存远程 token，不直连远程服务 |
| 本机 Codex CLI | 在用户选定的本地工作目录执行会话 | 本机线程与工作文件 | 不读取服务端数据库、不自行管理共享需求 |

## 四、核心数据模型

| 实体 | 关键字段 / 关系 | 说明 |
|---|---|---|
| 用户 | `id`、显示名、登录名、密码摘要、创建时间 | 服务端自管的最小账号体系；首次访问可注册后直接登录。 |
| 项目 | `id`、名称、归档标记、创建/更新人 | 需求的服务端归属。首期任意已登录用户均可创建、改名、归档。 |
| 需求 | `id`、`projectId`、标题、简要需求说明、状态、版本、创建/更新人 | 正文只存业务说明；完整 PRD/图片/文档作为附件，不把 PRD 原文机械复制进“需求说明”。 |
| 评论 | `id`、`requirementId`、正文、作者、时间 | 围绕一个需求的协作记录。 |
| 附件 | `id`、`requirementId`、存储键、文件名、媒体类型、大小、校验和、上传人 | 元数据在 PostgreSQL；原始字节位于 `REQUIREMENTS_ATTACHMENT_ROOT` 下由服务生成的相对存储键。原始文件名不参与路径计算。 |
| 审计记录 | 操作人、资源、动作、前后摘要、时间 | 项目、需求、评论、附件和状态变化均保留操作记录。 |
| 本机项目目录映射 | `remoteProjectId`、绝对本机路径、校验时间 | 仅存在本机；服务端不知道任何开发者的磁盘路径。 |
| 本机会话 | 本地会话 ID、远程需求 ID、开工版本与审计水位线、Codex 线程 | 仍由现有本机会话运行时管理，不上传至远程需求服务。 |

需求状态固定为：`草稿、待开发、开发中、测试中、已完成、暂缓`。已登录用户可以直接切换为任意状态；不额外阻止跳阶段，每次变更写审计记录。

## 五、关键流程与边界

### 5.1 登录与请求转发

```
浏览器 → localhost BFF：注册 / 登录 / 当前用户
本机 BFF → 远程需求服务：认证请求
远程服务 → BFF：access token / 用户资料
本机 BFF：仅在本机 V2 数据目录保存 token
浏览器 ← localhost BFF：同源会话结果
```

浏览器不接触远程 token，也无需处理 CORS。服务端对 BFF 的请求按 Bearer token 识别用户。

### 5.2 需求协作

```
选择项目 → 查看列表/看板 → 新建或编辑需求
   → 填写简要需求说明、上传完整材料 → 服务端写入数据/审计
   → 添加评论、切换任意状态 → 服务端发布变更事件
   → 各本机 BFF 转发 SSE → 已打开页面刷新相应局部
```

附件的上传、下载均是“浏览器 → 本机 BFF → 远程服务 → 服务器受控附件目录”的流式链路。浏览器不拿存储凭证，也不访问主机路径、静态文件地址或存储键。

### 5.3 从需求创建本机 Codex 会话

```
需求详情点击「在本机开始对话」
        │
        ▼
本机 BFF 校验：当前项目是否已有可访问的本机工作目录
   │ 无映射/目录不可访问 → 返回设置入口，不创建会话
   ▼
记下开工版本与审计水位线（不下载任何材料，ADR-0003）
   ▼
创建现有 Codex 本机会话
   │ developer instructions = 几百字的需求卡（编号、标题、状态、说明、材料清单、上次结论、自上次以来的变化）
   │ dynamicTools = suduo_* 需求工具（查需求 / 评论 / 附件 / 确认版、看附件、拉确认版、读写结论笔记、发评论、发布确认版）
   ▼
会话页打开；Codex 在映射的本机工作目录运行，需要什么信息就调工具（工具在本机服务执行，不受沙箱档位影响）
```

工具实时取数，并以开工版本与水位线为分界回答「开工以后的变化」；只读工具不确认，发评论、发布确认版在工具调用里停住、等用户在审批坞确认（ADR-0004 红线）。取数机制见 [ADR-0008](../06_决策记录/ADR-0008-需求会话取数改为Codex客户端自定义工具.md)。2026-10-01 之前创建的需求会话是「旧版会话」（快照 + 现状文件，已不再刷新），界面提示新建。

## 六、前端信息架构

> 2026-09-29 起按 UI/UX 产品化重设计实现（旧版「顶栏 + 三模式」已替换）。细节见 [client/web 架构](client-web-架构.md)。

```
左侧栏（展开 240 / 收起 56）：项目切换 → 搜索（⌘K）→ 我的工作 / 需求 / 会话 / 概览 → 设置、账号

/my                                   我的工作：需要你处理、我的需求、会话、最近动态
/p/:项目/requirements                 需求看板 / 列表；点卡片开右侧速览（?peek=编号）
/p/:项目/requirements/:编号           需求详情：描述、材料与确认版、活动、属性、开始会话
/p/:项目/overview                     概览：状态分布、流转趋势、停滞需求、最近动态
/sessions[/:会话]                     会话：跨项目会话列表 | 消息流（回合时间线）+ 审批坞 + 输入框 | 检查面板
/settings/:分组                       设置：外观、通知、账号、需求服务、代码目录、模型服务、执行与安全、Skills、MCP、网络代理、诊断、关于
/setup、/login                        首启向导（连接服务 → 登录 → 环境检查 → 关联代码目录）与登录
```

根路由统一拦截：需求服务未配置去 `/setup`，未登录去 `/login?redirect=`。旧地址（`/requirements`、`/requirements/:id`、`/overview`、`/sessions?sessionId=`、`/settings#组`）全部重定向到新地址。

视觉：语义令牌驱动的亮 / 暗双主题（默认跟随系统），舒适 / 紧凑两档密度，正文 14px；文字与底色对比度 ≥ 4.5:1。

会话页遵循以下交互边界：

- 只呈现可理解的执行动作和进度：文字与步骤按时间交错，连续步骤聚成一行摘要（「查看了 6 个文件 · 运行了 2 条命令 · 18 秒」）默认折叠；推理只显示 Codex 给出的摘要，不展示伪“思考过程”。
- 每个回合结束有一行摘要（用时、改动文件数、命令数）；回合里的错误成为该回合内的错误卡，重连显示「正在重连（第 N/M 次）」。
- 审批固定在输入框上方（审批坞），不随消息流滚走、不弹模态；焦点在确认卡上、或没停在任何控件上时，⏎ / Esc 即同意 / 拒绝。
- 模型、推理强度、确认方式在输入框底栏按会话设置，只影响这个会话的下一轮。
- 输入框支持图片附件与 `@` 本地项目文件引用；运行中 Enter 并入这一轮、Tab 排到这一轮之后。不把它描述或实现成任意远程会话文件上传。

## 七、安全、审计与配置

| 关注点 | V2 约定 |
|---|---|
| 账号 | 内网最小账号密码：注册、登录、当前用户；不做密码找回、角色、权限后台。 |
| 认证 | 远程服务签发有有效期的 Bearer token；本机 BFF 保存，浏览器不保存。具体签名/过期配置随 T1 实现固化。 |
| 权限 | 首期所有已登录用户均可管理项目和需求；所有写操作记录操作者。后续由服务端管理平台扩展权限。 |
| 文件 | 远程服务校验文件大小、类型和归属；仅接受服务生成的相对存储键。上传先写受限暂存目录并计算校验和，成功后原子移动至专用附件目录；下载和删除均按附件 ID 鉴权并留审计，不开放静态目录。 |
| 本机路径 | 只允许用户在本机设置项目→绝对目录映射；创建会话前实时检查目录存在且可访问。 |
| 审计 | 不以状态流转规则替代审计；状态可任意切换，但必须留下操作者、时间和前后值。 |

远程服务的最低配置包括数据库连接、附件根目录、token 签名密钥和服务监听地址；`REQUIREMENTS_ATTACHMENT_ROOT` 必须是专用、可写且不由 Web 服务器静态暴露的绝对目录。本机配置包括远程服务地址、登录态和项目目录映射。密钥不写入前端构建物或仓库。

## 八、演进与切换

1. V2 不读取旧 SQLite/TAPD 数据，不做数据迁移、兼容层或双写。T1～T3 已交付远程协作、本机工作台、附件和实时协作主链路。
2. **T4 已完成**：旧 TAPD/本地需求的路由、服务、仓储、契约、UI 入口与迁移整体移除，迁移链重写为只服务 V2 的干净 schema。用户项目目录内的 `requirements/.tapd.yaml` 经逐项确认后清理，Codex 配置始终未被触及。
3. **切换与回滚按 D4**：旧库与旧数据一律不保留、不做升级迁移；本机 SQLite 视为可丢弃运行态，回滚 = 降到旧发布版本 + 库按新版本重建。代价是本机已配的目录映射与已同步的需求材料快照需重新配置与同步。
4. **T5 暂缓**：T5-1（部署资产）与 T5-2（本机配置与回滚说明）已交付；T5-3（全新机器闭环验收与发行放行）挂起于外部环境与授权。Docker/compose 路径、容器 `HEALTHCHECK`、备份恢复演练、全新机器安装与回滚演练**均未实跑**，不得推定通过。
5. 后续再建设服务端管理平台，统一处理账号和项目权限；不在当前客户端硬塞角色逻辑。

## 九、业务线与功能清单

V2 是 **3 条业务线 + 1 条横切支撑线**。L3 是 V2 立项的理由——没有它，L1 只是普通需求看板、L2 只是普通 AI 编码工具。

```
L1 共享需求协作 ──┐
                  ├──→ L3 需求→会话桥接
L2 本机 AI 开发 ──┘
          L4 平台 · 安全 · 发行（横切）
```

### L1 共享需求协作 —— `cloud/server` `/v2`（远程）

| 功能 | 端点 | 关键约束 |
|---|---|---|
| 账号 | `POST /auth/register`、`/auth/login`；`GET /auth/me` | 内网最小账号；无找回密码、无角色 |
| 项目 | `GET/POST /projects`；`PATCH /projects/:id` | 创建 / 改名 / 归档恢复；`expectedVersion` 乐观锁 |
| 需求 | `GET/POST /projects/:id/requirements`；`GET/PATCH /requirements/:id` | 游标分页；六状态任意跳转；仅正文（title / summary / status）实变时 `version` 递增，附件增删与产物发布只刷新 `updated_at` |
| 评论 | `GET/POST /requirements/:id/comments` | — |
| 附件 | `GET/POST /requirements/:id/attachments`；`GET/DELETE /attachments/:id/content` | 300 MiB/个、20 个/需求、扩展名 allowlist、SHA-256；存储键由服务生成；staging→fsync→rename 原子落盘；逻辑删除先于物理删除；HTML/SVG 强制 `attachment` + `nosniff` 且不预览 |
| 审计 | `GET /audit` | 创建/编辑/状态/评论/附件/下载全留痕，含操作人与前后值 |
| 实时 | `GET /events`（SSE） | 需鉴权；事件只带资源标识 + 版本 + 变更类型，**不承载正文** |
| 健康 | `GET /health` | 含数据库状态与 schemaVersion |

### L2 本机 AI 开发会话 —— `client/server` `/api/v1` + `client/web` `SessionRuntime`（本机）

会话生命周期（创建 / 列表 / 详情 / 删除 / `run-status` / `interrupt`）· 消息与事件流（`messages`、`events`、`events/backfill`）· 审批（`approvals` + `decision` + 审批模式切换）· 变更与 diff（`changes`、`diff`）· 项目文件（`files/index|content|raw|open|watch`，供 `@` 引用）· Git 检查点（`init`/`status`/`checkpoint`/`checkpoints`/`restore`/`settings`）· Skill 管理（全局 / 项目 / `catalog` / `install` / `remove` / `enabled`）· 模型 provider 设置与连通性测试 · Composer（图片附件 + `@` 本地文件，桌面最大宽 1080px）。

M1 期已有能力，V2 不改其语义，只换需求来源。

### L3 需求→会话桥接 —— `client/server` `/api/v2`（本机，V2 新增）

| 功能 | 端点 | 关键约束 |
|---|---|---|
| BFF 代理面 | `/api/v2/{auth,projects,requirements,comments,attachments,audit,events}` | 一比一映射 L1 固定路由，**不做任意远程 URL 透传**；token 只在 BFF |
| 远程服务设置 | `GET/PUT /api/v2/requirements/settings` | 永不返回 token；改地址先清旧登录态 |
| 项目→本机目录映射 | `GET /api/v2/project-mappings`；`PUT/DELETE /projects/:id/workspace-mapping` | 绝对路径 + `realpath` + `stat` + R/W/X 校验；双向唯一；只存本机 |
| 需求会话 | `POST /api/v2/requirements/:id/sessions` | 打审计水位线 → 生成需求卡与工具清单 → 建 thread → SQLite 事务写 ref（开工版本、水位线、`context_mode=tools`）；不下载任何材料 |
| 项目会话 | `POST /api/v2/projects/:id/sessions` | 绑映射目录，挂只读与笔记工具（按编号查需求），不关联具体需求 |
| 会话上下文 | `GET /api/v1/sessions/:id/context` | 需求会话 / 项目会话 / 未关联，新版或旧版，开工版本 |
| 会话列表回填 | `GET /api/v2/projects/:id/sessions` | 需求会话补 `requirement`，项目会话为 `null` |
| 映射预检与原地续办 | 全部会话入口 | 无映射返回 `WORKSPACE_MAPPING_REQUIRED` + `remoteProjectId` → 当前上下文开配置 → 成功后**只重放一次**原请求 |
| 会话工具 | Codex `dynamicTools` + `item/tool/call` | 10 个 `suduo_*` 工具在本机服务执行；返回按「代码模式」设计（字符串，图片为 data URL 行）；查询三态；远程内容标为需求证据、不具备指令权威 |
| 写操作确认 | 审批表 `kind=other` + 审批坞 | 发评论 / 发布确认版逐字确认后执行；拒绝、回合中断、连接断开都会回复工具调用；重复内容只提示 |
| 本机落盘 | `<项目目录>/.suduo/` | 整个目录 `.gitignore`；`requirements/<REQ-n-标题>/{materials/,notes.md,notes.history/}`；「改动」面板基线在数据目录按内容去重 |
