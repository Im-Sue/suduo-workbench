# SuDuo V2 会话回答里的文件路径可点击预览

> 一句话：Codex 回答里写到的项目文件（`src/a.vue:401` 这类），无论写成行内代码还是正文，点一下就在右侧文件面板打开并定位到那一行，像 Codex CLI / Claude Code CLI 那样。｜最后更新：2026-10-01
>
> 依赖：已有的右侧文件面板预览（含按行定位）与 Markdown 链接处理（`client/web/src/ui/markdown-links.ts`，需求会话上下文重做 4.6）。

---

## 需求描述

会话页已经能预览项目文件，回答里的 Markdown 链接（`[文字](src/a.ts:12)`）也能点开。但 Codex 实际最常见的写法是**行内代码**：「入口是 `Appreciation-admin/src/views/.../MerchantProductBusinessData.vue:401`」，这类路径现在只是灰底文字，要验证 Codex 说得对不对，只能自己去文件树里一层层找。

本需求让回答里指向项目文件的路径都可以直接点击：在右侧文件面板打开、滚到并高亮那一行。

## 原话（verbatim）

> 「会话方向：图1，我们现在既然 具有 文件预览功能，那么llm的消息里的 文件路径、文件说明是否可以像正常的codex cli或者claude code cli一样可以进行直接点击预览？」

（图 1：REQ-1 会话里 Codex 的回答，红框处是两条行内代码形式的文件路径，带行号。）

---

## 二、背景与目标

会话是「人 + 自己的 Codex」的私人工作台，核心动作是**核对 Codex 的结论**。回答里的文件路径就是它给出的证据，一键打开证据是核对成本最低的方式。

| 现在 | 之后 |
|---|---|
| Markdown 链接可点；行内代码、正文里的路径不可点 | 三种写法都可点，统一在右侧文件面板打开并定位到行 |

**目标**：回答里出现的项目文件路径，只要文件确实存在，就能点开；不是路径的行内代码（`receiverSnapshot`、`order.total`）不能被误当成链接。

---

## 三、讨论与决策

> 状态：用户 2026-10-01 确认按推荐方案：行内代码 + 正文都识别，文件须在项目索引里存在。

### 讨论：哪些写法算文件路径

- **推荐**：Markdown 链接（已支持）+ 行内代码 + 正文里的路径三种都识别。支持的形状沿用现有规则：`src/a.ts`、`./src/a.ts`、`src/a.ts:12`、`src/a.ts:12:5`、`src/a.ts:12-20`、`src/a.ts#L12`、项目目录下的绝对路径。
- **防误判**：只有本机确认**项目目录里确实存在**的文件才变成链接。`receiverSnapshot` 不算候选、不去问；`order.total`、`a/b` 是候选但不存在，也不会变链接。
- 实现时改为新增本机只读接口 `POST /api/v1/projects/:id/files/exists`，按路径批量确认（一次最多 200 条，只认项目目录内的普通文件，符号链接越界也不算）。原想用现有文件索引，但它最多 8000 条，大项目会被截断。
- 代码块（```）里的内容不处理：那是代码，不是引用。
- 目录（`src/views/`）P0 不加链接。

### 讨论：点击后做什么

- **推荐**：单击 = 右侧文件面板预览，滚到并高亮该行（已有能力）；⌘ / Ctrl + 单击 = 用本机编辑器打开（已有「打开位置」能力，按本机探测到的 VS Code，没有就用系统默认应用）。悬停显示完整相对路径和「点击预览 · ⌘ 点击在编辑器打开」。
- 样式：和现在的文件链接一致（主色、下划线）；行内代码保留等宽灰底，只加下划线与手型光标。

### 讨论：哪里生效

- **推荐**：会话里 Codex 的回答正文、计划（plan）文本。用户自己发的消息、思考摘要、工具卡片不在本期（工具卡片里的文件已经有各自的打开入口）。
- 房间里 Agent 的回答：房间成员电脑上大多没有这份代码，本期不做。

---

## 四、功能 / 范围

| 项 | 说明 |
|---|---|
| 做什么 | 会话回答正文里的行内代码路径、正文路径变成可点击链接（Markdown 链接保持现状） |
| 谁用 | 所有会话页用户 |
| 预期结果 | 点击后右侧文件面板打开该文件并定位高亮到行；⌘ / Ctrl 点击用编辑器打开 |

## 五、业务规则

| 编号 | 规则 |
|---|---|
| R1 | 只认项目目录内的文件；项目外的绝对路径、`~` 开头的路径保持纯文字 |
| R2 | 候选（带 `/` 或有扩展名、无空白、在项目内）经本机确认存在才加链接；确认中或查询失败时只显示文字 |
| R3 | 带行号时定位到起始行；只有列号或范围时也只定位到起始行 |
| R4 | 代码块里的内容不加链接 |
| R5 | 确认结果按会话页缓存：存在的一直有效；不存在的 15 秒后回答再渲染时重新确认（Codex 可能刚建了这个文件）；之后被删除的文件点开时，面板说明打不开 |

## 六、边界 / 不做项

- 不做目录链接、不做房间消息里的路径、不做用户消息与工具卡片里的路径。
- 不改 Codex 的输出习惯（不要求它改写成 Markdown 链接）。

## 七、验收

1. 图 1 那条回答里的两处 `…vue:401`、`…vue:1` 可点，点开后右侧文件面板显示该文件并高亮第 401 行。
2. `receiverSnapshot`、`order.total` 等行内代码不变成链接。
3. 正文里（不在反引号中）的 `src/cart.js:16` 可点。
4. ⌘ 点击用编辑器打开；项目外路径不可点。
5. 代码块里的路径不可点。

## 实现记录（2026-10-01）

| 项 | 实现 |
|---|---|
| 识别 | 行内代码：`ui/markdown.tsx` 的 `code` 渲染器（代码块里的不处理）；正文：remark 插件 `ui/markdown-paths.ts` 切出像路径的片段，中文贴着写时按候选剥掉前后中文与句末的点 |
| 确认存在 | 本机新增只读接口 `POST /api/v1/projects/:id/files/exists`（一次最多 200 条，只认项目内普通文件）；前端 `ui/file-existence.ts` 同一轮渲染攒成一批、按会话页缓存，不存在的 15 秒后重新确认 |
| 打开 | 单击右侧文件面板定位到行；⌘ / Ctrl 单击用 VS Code 打开并跳到行（`code -g 文件:行`，`files/open` 新增可选 `line`），本机没有 VS Code 时用系统默认应用 |
| 范围 | 只在会话页生效（提供了文件存在确认的地方）；需求页、房间、悬浮窗口里不识别 |

验证：本机 REQ-1 真实会话里两处 `…vue:401`、`…vue:1` 变成链接，点击后右侧预览定位到第 401 行；`receiverSnapshot` 不变。
