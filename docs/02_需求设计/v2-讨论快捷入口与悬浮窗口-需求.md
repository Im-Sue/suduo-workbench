# SuDuo V2 讨论快捷入口与悬浮窗口

> 一句话：在任何页面都能一键进入讨论——需求预览面板里直接「进入 / 创建讨论」，右下角有个悬浮入口能弹出房间叠放（像 Mac 程序坞的叠放），房间在一个可拖动、可拉伸的悬浮窗口里打开，不用离开当前页面。｜最后更新：2026-10-01
>
> 依赖：[项目聊天房间与共享 Agent](v2-项目聊天房间与共享Agent-需求.md)（房间、话题、共享 Agent 的全部能力照用，本需求只改「从哪进、在哪看」）。竞品参考：Tutti 的群聊悬浮窗（2026-10-01 实际查看：标题栏拖动、四边四角拉伸、最小 320×384、不超出浏览器、可收起、窄屏不显示）。

---

## 需求描述

房间现在只能从侧栏「讨论」页或需求完整页的「讨论」区块进入，进去就离开了手上的页面：在看板上看需求、在会话里跟 Codex 对话时，想去房间问一句，得切页面、再切回来。

本需求加三处入口和一种打开方式：

1. 需求预览面板（看板右侧弹出的那个）里加「进入讨论 / 创建讨论」按钮。
2. 页面右下角一个悬浮入口，点开弹出本项目的房间，房间多时像 Mac 程序坞的叠放一样上下滚动挑选。
3. 房间在一个悬浮窗口里打开，可以拖动、拉伸，放在页面旁边边看边聊。

## 原话（verbatim）

> 「群聊/讨论方向：
> 1. 图2，这个需求的 预览弹窗 里应该有一个按钮：创建需求讨论房间 或者 进入需求讨论房间
> 2. 右下角或者右下角 应该设计一个 悬浮图标，可以快速进入房间。点击可以弹出多个房间，如果房间太多 类似 mac的 废纸篓的特效 可以上下滚动选择房间
> 3. 房间的打开 可以是一个 悬浮窗口，类似 tutti 一样的弹窗。这样方便我左右拖拉、移动。」

（图 2：需求看板，右侧是 REQ-1 的预览面板，底部有「开始会话」「打开完整页」。）

## 二、背景与目标

房间的定位是「团队即时讨论空间」，即时讨论的关键是**随手就能开口**。现在入口藏在侧栏，打开就要离开当前工作，和「即时」相矛盾。

| 现在 | 之后 |
|---|---|
| 进房间要切到「讨论」页 | 任何页面右下角一点就弹出房间 |
| 需求预览面板里看不到讨论 | 预览面板里一键进入 / 创建这条需求的讨论 |
| 房间占满整页 | 房间在悬浮窗口里，可以和看板、会话并排 |

## 三、讨论与决策

> 状态：用户 2026-10-01 确认按推荐方案（★ 两项：悬浮入口只列当前项目的房间；悬浮窗口一次一个，切换房间替换内容）。

### 讨论：需求预览面板里的按钮怎么表现

- **推荐**：放在面板底部、「开始会话」旁边，按这条需求已有的房间数决定：
  - 没有房间：「创建讨论」→ 打开现有的新建对话框（名字缺省「REQ-n 讨论」，可选拉人）→ 建好直接在悬浮窗口里打开。
  - 一个房间：「进入讨论」，有未读时带未读数 → 悬浮窗口打开。
  - 多个房间：「进入讨论 ▾」下拉：各房间（未读数）+「新建讨论」。
- 已归档的房间不出现在按钮里（完整页的「讨论」区块照常能看到）。

### 讨论：悬浮入口放哪、列哪些房间

- **推荐位置**：默认右下角；可以拖到左下角，松手吸附到最近的一边，位置记在本浏览器。窄屏（< 640px）和登录 / 初始化页不显示。
- 图标上显示本项目房间的未读总数，有人 @ 我时显示「@」角标。
- ★ **列哪些房间**：推荐**当前项目**的全部未归档房间（项目默认房间 + 各需求房间），与侧栏「讨论」页一致；不跨项目。
- 排序：@ 我的 > 有未读的 > 最近有消息的。

### 讨论：「像 Mac 废纸篓的效果」指什么

- **理解**：Mac 程序坞里点开「下载」「废纸篓」这类叠放时的**扇形展开**——房间沿一条从图标向上的弧线依次排开，越远越小、越淡。
- **推荐交互**：
  - 一屏最多排开约 8 个；更多时滚轮 / 触控板 / ↑↓ 键沿弧线滚动，两端的项渐隐。
  - 每项：房间类型图标（# 项目房间 / 需求房间）、名称、未读数。
  - 最下面固定一项「全部讨论…」，进入侧栏「讨论」页。
  - Enter 打开，Esc 或点空白处收起。
  - 系统开了「减少动态效果」时改成普通竖排列表，无弧线动画。
- 如果你说的是别的效果（例如网格展开），请指正。

### 讨论：悬浮窗口

- ★ **一次开几个**：推荐**一个**窗口；打开另一个房间时替换窗口里的内容（标题栏有房间切换下拉）。多窗口同时开会挡住页面，也更难管理未读。
- **拖动与拉伸**（照 Tutti）：
  - 按住标题栏拖动。
  - 四边四角都能拉伸，最小 360×420，不能拖出浏览器。
  - 位置和大小记在本浏览器。
- **标题栏**：房间名与类型、成员头像、「共享 Agent」、「在讨论页打开」（放大成整页）、「收起」（收回悬浮入口，窗口状态保留）、「关闭」。
- **内容**：与讨论页相同，包括消息流、输入框（@、文件、草稿）、话题和运行详情；话题和运行详情在窗口右侧分栏，分隔线可左右拖动。
- **跨页面保持**：切换页面时窗口不关。窗口打开且在前面时算「正在看」，消息记为已读，与讨论页同口径。
- **与讨论页的关系**：讨论页照旧可用。悬浮窗口里点「在讨论页打开」就关闭窗口、跳到该房间整页。
- **窄屏**（< 640px）：不弹窗口，直接跳到讨论页。

## 四、功能 / 范围

| 项 | 说明 |
|---|---|
| 需求预览面板按钮 | 创建讨论 / 进入讨论（含多房间下拉），打开到悬浮窗口 |
| 悬浮入口 | 右下（可吸附到左下），未读角标；点击弹出房间扇形叠放，可滚动挑选 |
| 悬浮窗口 | 单窗口，拖动、八向拉伸、收起、在讨论页打开、关闭；内容与讨论页一致；跨页面保持 |
| 谁用 | 所有登录用户 |

## 五、业务规则

| 编号 | 规则 |
|---|---|
| R1 | 悬浮入口与扇形列表只列当前项目的未归档房间，排序：@ 我 > 未读 > 最近消息 |
| R2 | 同时只有一个悬浮窗口；打开别的房间替换内容，草稿按房间保留（已有能力） |
| R3 | 窗口位置、大小、悬浮入口所在的边，都记在本浏览器（个人偏好，不上服务器） |
| R4 | 窗口打开且未收起时，该房间计为「正在看」：新消息不计未读 |
| R5 | 需求预览面板：0 个房间显示「创建讨论」，1 个显示「进入讨论」，多个显示带下拉的「进入讨论」；已归档房间不列入 |
| R6 | 窄屏（< 640px）不显示悬浮入口与悬浮窗口，入口改为跳转讨论页 |

## 六、边界 / 不做项

- 不做多窗口同时打开；不做弹出成独立的系统窗口（浏览器画中画）。
- 不做跨项目的房间列表。
- 不改房间、话题、共享 Agent 的任何业务规则；不新增后端接口。

## 七、验收

1. 看板上打开 REQ-1 预览面板：没有房间时「创建讨论」→ 建好后右下弹出悬浮窗口进入该房间；再次打开面板时按钮变为「进入讨论」。
2. 任意页面右下角点悬浮入口：弹出本项目房间的扇形列表，未读数正确；房间超过 8 个时可以滚动挑选；减少动态效果时为普通列表。
3. 悬浮窗口可拖动、八向拉伸，不出浏览器；刷新页面后位置和大小保持。
4. 在悬浮窗口里发消息、@ 共享 Agent、看话题与运行详情，与讨论页一致；切换页面窗口不关。
5. 收起后再点悬浮入口能恢复窗口；「在讨论页打开」跳到整页。
6. 悬浮入口拖到左边后吸附在左下，刷新后保持。

## 实现记录（2026-10-01）

纯前端，没有新增后端接口。主要文件在 `client/web/src/features/rooms/` 下：`window/`（悬浮入口、悬浮窗口、几何计算、偏好存储、窗口状态）、`components/RoomBody.tsx`（讨论页与窗口共用的对话区：面板状态由讨论页的地址或窗口状态提供）、`sections/RequirementRoomButton.tsx`（预览面板按钮）。

| 项 | 与上文的差异 / 补充 |
|---|---|
| 悬浮入口位置 | 默认离底部 120px（贴底会压住输入框的发送按钮）；左右吸附之外，上下位置就地保留 |
| 窗口层级 | 窗口在页面之上、对话框 / 菜单 / 提示之下；窗口里按不带修饰键的单键不触发底下页面的快捷键 |
| 焦点 | 每次打开 / 恢复都回到输入框；收起时焦点交还悬浮入口；从下拉菜单选房间后焦点不还给菜单按钮 |
| 窄窗口 | 窗口宽度不足 560 时，话题与运行详情盖住整个窗口（被盖住的区域不能被 Tab 到） |
| 正在看 | 按「谁在看」分别登记：讨论页与悬浮窗口同时开着同一个房间时互不影响；收起时不算在看 |
| 偏好存储 | 窗口位置大小、话题栏宽度、悬浮入口位置记在本浏览器（读写失败当没记过） |

审查：独立审查无高危；三条中等问题（预览面板切换需求后新建讨论的默认名字、恢复时焦点、减少动态效果下选房间后焦点被抢回）与低优先级的手势、滚动吸附、触屏阈值等均已修。
验证：浏览器实测预览面板「进入讨论」→ 窗口打开且焦点在输入框；拖动、八向拉伸、不出浏览器；收起 → 恢复焦点回到输入框；站内切页面窗口保持；扇形叠放（12 个房间时沿弧线滚动、两端渐隐）。
