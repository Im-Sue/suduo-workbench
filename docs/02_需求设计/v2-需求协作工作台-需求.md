# SuDuo V2 需求协作工作台需求设计

> 一句话：让产品、开发、测试在同一个本机 SuDuo 工作台中共同管理远程项目需求，并从项目或需求创建受本机目录映射约束的 Codex 会话。｜最后更新：2026-08-14

## 需求描述

重构当前以本地 SQLite/TAPD 为中心的需求看板。V2 建立独立的内网远程需求服务，作为项目、需求、评论、附件和审计的唯一共享真相；每个人仍在自己的电脑上打开 SuDuo，使用本机 Codex CLI 在本地工作目录中对话和开发。

本期的重点是流程处理、UI 交互闭环和配置化闭环：产品能创建需求并上传完整需求材料，所有角色都能查看和拉取材料，并在满足本机目录映射的前提下从项目或需求创建会话。服务端不处理或保存具体 Codex 指令、对话和执行过程。

## 原话（verbatim）

> “服务器上是后端服务端，所有的 UI 交互在本地机。例如产品在本地 suduo 查看需求列表、需求管理；开发在本地也一样看到，无论是开发和产品、测试都可以通过 suduo 进入需求查看、操作、评论，然后在 suduo 通过本地 codex cli 创建会话。”
>
> “服务端有项目-需求的机制。本地工作区在创建对话前本地校验一下是否给对应项目配置本地工作目录。项目-工作目录。”
>
> “草稿、待开发、开发中、测试中、已完成、暂缓……不需要做什么解释，做好操作记录就行了。”
>
> “旧数据不考虑，只考虑整体升级、改造，我觉得 tapd 都没必要兼容。”

## 二、背景与目标

当前本地需求、TAPD 集成和会话在一个本机应用中，难以把产品、开发、测试的需求协作共享起来。V2 将“共享需求”与“本地 AI 开发”分开：远程服务保证协作数据一致，本机保证 Codex 对本地源码和工具的访问。

- **目标 1**：所有已登录团队成员在本机 SuDuo 中看到同一组远程项目与需求。
- **目标 2**：一个需求能承载简要说明、完整需求材料、评论、状态与操作记录。
- **目标 3**：从项目或需求创建会话前，明确校验“远程项目 → 本机工作目录”映射，避免 Codex 在错误目录执行。
- **目标 4**：在唯一工作台壳内完成需求、会话、设置的完整、清晰的 Symphony 风格操作闭环。
- **目标 5**：不再把 TAPD 作为 V2 的运行时依赖，也不为兼容旧数据引入双写或迁移负担。

**端到端示例**：产品小李在本机登录 SuDuo，创建“订单导出优化”项目下的需求，只填写供看板阅读的简要需求说明，再上传确认过的 PRD、原型和样例文件。开发小王在自己的电脑看到同一需求，设置该项目映射到本机代码目录，点击“在本机开始对话”。SuDuo 拉取该需求的当前快照及附件到本机材料目录，创建 Codex 会话并携带需求标识和材料路径。小王的对话仍只在本机运行；产品可继续在统一工作台的需求模式中评论或更新材料。

## 三、讨论与决策

| 决策点 | 最终决策与理由 |
|---|---|
| 运行形态 | 远程服务只做共享需求协作；UI、BFF 和 Codex 都留在本机。这样既能共享需求，又不把本机源码/CLI 暴露到服务器。 |
| TAPD | V2 不兼容 TAPD、不双写、不迁移旧数据。TAPD 相关运行时代码和旧本地数据在最终切换阶段清理。 |
| 账号 | 内网最小账号密码体系：无账号则注册并登录；不做找回密码、复杂角色或权限后台。 |
| 项目权限 | 首期所有已登录用户都可创建、改名、归档项目；审计记录操作者，后续再由服务端管理平台收紧权限。 |
| 状态 | 固定为草稿、待开发、开发中、测试中、已完成、暂缓；任意状态可直接切换，以审计记录而非强制流转解释变化。 |
| 文件 | 共享附件暂存于远程服务器由 `requirements-service` 独占的受控硬盘目录；浏览器经本机 BFF 和远程服务上传、下载，不直连服务器磁盘或静态文件地址。 |
| 本机访问远程服务 | 浏览器只访问 localhost；本机 `client/server` 保存登录态并代理远程 API、文件流和实时事件。 |
| 工作台壳与路由 | `/` 是 V2 唯一的产品工作台壳。需求、会话、设置是壳内模式；`/requirements`、`/sessions`、`/settings` 只可作为恢复模式的深链接，不能各自渲染第二套顶栏、侧栏或独立产品。 |
| 登录入口 | 未登录时也渲染统一工作台壳，在主工作区显示登录/注册卡；登录成功后回到此前请求的工作台模式。 |
| 会话与需求 | 会话不存到远程服务。所有已登录角色都可从项目或需求创建本机 Codex 会话；项目会话仅绑定本机映射目录，需求会话额外注入创建时的远程需求快照，并在 T3 把附件拉到本机材料目录。 |
| 后续阶段拆分 | T4 只处理旧 SQLite/TAPD 数据及对应旧运行时能力的受控清理；部署发行、安装配置与完整环境验收独立为 T5。T4 不执行部署，T5 不重复承担旧数据清理。 |

## 四、功能 / 范围

### 4.1 最小账号与登录

| 项 | 说明 |
|---|---|
| 做什么 | 注册、登录、查看当前用户、退出本机登录态。 |
| 谁用 | 所有内网用户。 |
| 怎么触发 | 首次打开未登录的本机 SuDuo 时在统一壳主区直接登录/注册，或在统一工作台的设置模式中切换账号。 |
| 预期结果 | 有账号直接登录；没有账号可注册后直接进入工作台。 |

### 4.2 项目与需求协作

| 项 | 说明 |
|---|---|
| 做什么 | 创建、改名、归档项目；在项目下创建、查看、编辑需求，切换状态、评论和查看审计。 |
| 谁用 | 已登录的产品、开发、测试。 |
| 怎么触发 | 统一工作台需求模式中的项目选择器、看板/列表、需求详情和编辑操作。 |
| 预期结果 | 任何成员都能在本机看到同一份服务端数据，操作后其他打开的客户端可更新。 |

需求的“简要需求说明”用于看板和快速理解，应为短说明，不直接复制完整 PRD 正文。完整 PRD、原型、图片、Word、Excel 等以附件保存。

### 4.3 附件与需求材料

| 项 | 说明 |
|---|---|
| 做什么 | 在需求上上传、列出、下载、删除附件；从需求创建会话时将所需材料同步到本机。 |
| 谁用 | 有需求操作权限的已登录用户。 |
| 前置条件 | 需求存在；上传者已登录。 |
| 预期结果 | 附件归属明确、可审计；用户不需要了解服务器目录、存储键或主机路径。 |

T3 默认单附件上限为 300 MiB（314,572,800 字节），每个需求最多保留 20 个未删除附件。默认允许常用办公文档、文本、图片、压缩包，以及 HTML、SVG；HTML/SVG 仍是不可信材料，只允许下载，不提供在线预览或执行入口。附件名只用于展示和下载文件名，不能参与服务器路径计算。

### 4.4 项目—本机工作目录映射

| 项 | 说明 |
|---|---|
| 做什么 | 为一个远程项目配置绝对工作目录，查看、修改或移除本机映射；配置入口可在工作台设置模式中集中管理，也必须能由创建会话的当前操作上下文直接打开。 |
| 谁用 | 任何准备从该项目或其需求创建本机会话的已登录用户。 |
| 前置条件 | 已登录并可看到该远程项目。 |
| 预期结果 | 映射只影响当前电脑；创建会话前重新校验目录存在且可访问。映射缺失、目录不存在或权限失效时不创建会话，用户在当前上下文完成配置后可继续原操作。 |

### 4.5 从项目或需求创建本机 Codex 会话

| 项 | 说明 |
|---|---|
| 做什么 | 在项目上下文创建项目级本机 Codex 会话，或在需求详情创建关联需求的本机 Codex 会话；需求会话拉取创建时的需求快照和附件。 |
| 谁用 | 所有已登录用户，不以产品、开发、测试角色区分。 |
| 前置条件 | 当前项目存在有效本机目录映射。 |
| 预期结果 | 项目级会话仅在映射目录中运行；需求会话关联需求 ID 与快照版本，Codex 可从本机材料目录读取需求和附件。无有效映射时，在当前操作上下文提示并提供“配置当前项目工作目录”；配置成功后继续原创建操作，而不是跳到另一套页面后要求用户重新定位。 |

### 4.6 统一工作台 UI/UX 闭环

| 项 | 说明 |
|---|---|
| 做什么 | 在 `/` 统一工作台壳内提供需求、会话、设置三种模式，复用同一顶部栏、左栏框架、会话运行态、消息、审批、工具调用和 Composer；在需要配置或处理错误时给出当前上下文可完成的下一步。 |
| 谁用 | 所有本机 SuDuo 用户。 |
| 预期结果 | 用户能完成“登录 → 选项目 → 管理需求/材料 → 从项目或需求发起会话 → 必要时原地配置目录并续办 → 在同一工作台进入会话 → 返回需求协作”的闭环。深链接只能恢复当前模式，不能形成第二套交互系统。 |

## 五、业务规则

| 编号 | 规则 | 说明 |
|---|---|---|
| R1 | 远程服务是共享需求真相源 | 项目、需求、评论、附件元数据和审计不再以本地 SQLite 或 TAPD 为依据。 |
| R2 | 项目归属必填 | 每个需求必须属于一个服务端项目；项目归档后不再创建新需求。 |
| R3 | 状态任意切换 | 可在六个固定状态间任意切换；每次变更记录操作人、时间、前后状态。 |
| R4 | 所有协作写操作可追溯 | 创建/编辑/归档项目，创建/编辑需求，状态变更，评论与附件操作均写审计。 |
| R5 | 需求说明与完整材料分离 | 简要需求说明用于概要；完整 PRD 不被强制复制到说明字段，作为附件/材料保存。 |
| R6 | 目录映射仅本机保存 | 远程服务不保存、不同步用户电脑路径。 |
| R7 | 未映射不得创建会话 | 若项目没有可访问的本机工作目录，必须阻止项目级和需求级会话创建；在当前上下文提供配置映射并于成功后续办。 |
| R8 | 会话使用可复现快照 | 创建时记录需求版本并下载材料；已有会话不因远程需求更新而隐式改变上下文。 |
| R8.1 | 项目会话不伪造需求快照 | 从项目创建的会话只绑定该项目的本机映射目录，不虚构需求 ID、版本或材料快照；从需求创建时才适用 R8。 |
| R9 | 服务端不处理 Codex 对话 | 服务端不得运行 Codex、保存消息、执行工具或代理具体 CLI 指令。 |
| R10 | 浏览器不直连远程依赖 | 所有远程 API、附件流、实时事件均经本机 `client/server` BFF。 |
| R11 | 共享附件受控落盘 | 远程服务仅在专用附件根目录下按服务生成的相对存储键读写；原始文件名不参与路径计算，上传完成前不得对下载接口可见。 |

## 六、边界 / 不做项

- 不做 TAPD 接口、TAPD 双写、TAPD 数据迁移或旧任务兼容。
- 不做服务端 Codex、云端会话、远程代码目录挂载或服务端命令执行。
- 不做密码找回、角色权限、组织/租户、账号管理后台；后续独立设计服务端管理平台。
- 不做状态机守卫、审批流或“为什么可以跳状态”的解释机制。
- 不改变已经可用的 Codex 运行时、审批、Skill、Composer 基础能力；V2 只重接需求来源和页面结构。
- 当前不新增自动化测试工作；实施以构建、类型检查、lint 与人工闭环验收为准。

## 七、已闭环项与实施假设

| 项 | 当前结论 |
|---|---|
| 服务端技术栈 | 新增独立 Fastify 服务，数据用 PostgreSQL，附件使用挂载给远程服务的受控硬盘目录。 |
| 前端路由 | `/` 为唯一工作台壳；需求、会话、设置是壳内模式。`/requirements`、`/sessions`、`/settings` 仅用于恢复对应模式的深链接，始终复用根工作台的布局和运行时状态。 |
| 旧数据处理 | V2 从空数据开始；T4 在精确目标清单、预览与用户确认后清理已识别的旧 SuDuo SQLite/TAPD 数据及对应旧运行时能力，不删除用户项目目录或 Codex 配置。 |
| 发布形态 | T5 负责新服务与本机应用的部署发行；Docker、环境变量、数据库、服务器附件持久卷、流水线完全隔离。 |
| 未定技术常量 | token 有效期、密码强度、附件大小/类型上限和事件重连参数由 T1/T3 以配置项落地，不影响已确认的业务范围。 |

## 八、拆分预览

1. 共享契约与远程服务基础：DTO、错误码、PostgreSQL、注册登录、项目、需求、评论、审计。（T1，已验收）
2. 本机 BFF 与 V2 工作台：登录代理、项目目录映射、远程需求快照，以及统一 `/` 工作台内的需求/会话/设置模式；项目和需求都可在映射校验后创建会话。（T2，已验收）
3. 附件与实时协作：服务器受控硬盘目录的流式上传下载、会话材料拉取、SSE 经 BFF 转发。（T3，已验收）
4. 旧数据与旧运行时能力清理：以精确目标清单、预览、备份/回滚与用户确认处理旧 SQLite/TAPD 数据、路由、服务、配置和 UI 入口；不部署发行，不清理用户项目目录或 Codex 配置。（T4）
5. 部署发行与完整环境验收：requirements-service 的部署资产和持久卷、本机发行配置、全新环境闭环、切换与回滚记录。（T5）

| 本机映射 | 远程项目 ID、本机绝对目录 | 仅本机创建会话校验。 |

## 十二、交互 / 流程

```
首次使用
打开本机 SuDuo `/` → 无本机登录态 → 在统一壳主区注册或登录
  → 返回请求的工作台模式 → 选择/创建项目 → 新建需求（简要说明）→ 上传完整材料 → 评论/改状态

项目或需求发起会话
项目选择器或项目上下文点击「新建会话」，或打开需求详情点击「在本机开始对话」
  → 本机检查项目→目录映射
  ├─ 无效：在当前上下文打开「配置当前项目工作目录」→ 保存并校验 → 自动继续原操作
  └─ 有效：项目会话直接在映射目录创建；需求会话拉取固定需求快照/附件、写本机材料目录后创建
       → 切换同一工作台的会话模式并选中新会话

协作更新
任一用户编辑需求、评论、上传材料或切换状态
  → 服务端写数据和审计 → 发送事件 → 本机 BFF 转发 → 其他已打开页面局部刷新
```

## 十三、风险

| 风险 | 概率 | 影响 | 缓解 |
|---|---|---|---|
| 本机目录未映射或失效 | 中 | 无法安全创建会话 | 创建前强制本机校验，并给出设置入口。 |
| 形成多套应用壳 | 中 | 用户在需求、会话、设置间失去上下文，运行态割裂 | `/` 固定为唯一工作台壳；深链接仅恢复模式，组件和路由评审以“无重复顶栏/会话运行时”为验收项。 |
| 附件过大或中途中断 | 中 | 材料缺失、体验差 | 流式代理、服务端大小限制、清晰失败状态与重试。 |
| 服务端和本机版本不匹配 | 中 | 登录/API 失败 | 先稳定 `client/contracts`、`cloud/contracts`，BFF 按明确错误码提示升级或配置。 |
| 旧 TAPD 代码或数据残留 | 中 | 用户误入旧流程、产生双源认知或在清理前误删数据 | T4 先列精确清理目标、预览与备份/回滚，再移除旧运行时入口和已确认数据。 |
| 部署与完整环境差异 | 中 | 本机联调可用但发行环境配置不完整 | T5 独立完成 Docker、配置、持久卷、安装说明和全新环境闭环。 |
| 内网账号机制过于简单 | 中 | 后续账号治理成本 | 首期保留最小范围和审计，管理平台作为后续独立范围。 |

## Claude 解读

这不是把 Codex 搬到服务器，而是把“团队共同看和改的需求”搬到服务器，把“实际开发与对话”固定留在每个人的电脑。V2 的关键闭环是：远程项目/需求/材料 → 本机项目目录校验 → 带快照的本机 Codex 会话；UI 通过本机 BFF 安全地接入远程协作能力。

## 歧义点

无遗留待用户拍板项。共享附件已确定暂用远程服务器受控硬盘目录；附件限制、token 生命周期等属于实施配置，会在对应阶段以安全默认值落地，不改变本需求的业务边界。
