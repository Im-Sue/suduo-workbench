# 官网改版

> 一句话：把 suduo.dev 从「产品说明书」改成推广页——首屏讲团队协作、沟通与管理上的收益，「自己部署、代码留在本机」作为放心的理由；补上演示视频、首屏动画和运营基础（统计、自动部署、RSS）。｜最后更新：2026-10-05
>
> 前置：[官网](官网-需求.md)（2026-10-05 已上线 suduo.dev）与它的[技术设计](../03_开发计划/官网-技术设计.md)。改版的技术细节写进该技术设计新增的一节，不另开文档。

---

## 需求描述

官网 v1 的工程质量达标（全站 Lighthouse 99–100、中英一一对应、数据边界准确），但写法偏说明书：首屏讲「数据放在哪」而不是「团队得到什么」；最有辨识度的能力（共享 Codex、结论写回需求、概览与我的工作）在首页缺席；首页堆着「没有管理员」「Node 版本」等顾虑；访客除了「部署到你的服务器」没有更轻的下一步；没有任何访问数据，内容更新要手工发布。

改版后：团队负责人在首屏看懂「SuDuo 让团队和每个人的 Codex 协作、沟通更顺，进度也看得清」；有一段两分钟内的演示视频可看；运营上能看到访问数据，推到 main 自动上线。

## 二、背景与目标

**目标对齐**：用户要的核心卖点是**协作、沟通更方便**，其次是**管理更方便**。落到 SuDuo 现有能力上：

- **协作与沟通**：产品、开发、测试和每个人的 Codex 围着同一条需求沟通——评论、讨论房间、附件都在需求旁边；Codex 自己读需求和评论，结论写回需求；电脑上没有代码的人也能在讨论里 @ 共享进来的 Codex 问「现在是怎么实现的」。
- **管理**：看板、概览、我的工作——谁在做、做到哪、哪条停滞、开工后需求又改了，不用开会挨个问。这里的「管理」指**进度看得见**，不指权限管控（产品目前没有管理员功能）。
- **放心**：服务端自己部署，代码仓库和个人会话留在每个人的电脑上。v1 的主标题退为第三个卖点和副标题。

**模拟示例**：

1. 一位技术负责人从 V2EX 的帖子点进 suduo.dev。首屏标题说 SuDuo 让团队和每个人的 Codex 围着同一条需求协作，右侧一段 15 秒的循环动画：需求卡上点「开始会话」→ 本机 Codex 改代码、跑测试 → 结论作为评论回到需求。
2. 他往下看到「用之前 / 用之后」：之前需求在一个工具、讨论在聊天群、AI 做了什么只有开发自己知道；之后都在同一条需求上。
3. 他点「看 2 分钟演示」，在页面里播完视频，再往下看「适合谁」，确认团队规模和用法对得上。
4. 他点「私有部署」把链接转给负责运维的同事；同事在那一页看到系统要求、三步安装，以及「目前没有管理员，只在内网或 VPN 内开放」的提醒。
5. 运营这边，Cloudflare 的统计后台能看到这次访问来自 V2EX、看了哪几页；GitHub 的流量统计里能看到来自 suduo.dev 的访问。

- **背景**：v1 已上线；GitHub 主仓库 0 star、仓库主页未填官网；没有统计、没有留存触点；官网更新靠本机构建后手工 rsync。
- **目标**：
  1. 首屏十秒讲清协作、沟通、管理上的收益，并给出比「部署」更轻的下一步（看演示）。
  2. 首页出现三条核心工作流：从需求开工并写回、在讨论里问共享 Codex、用概览和我的工作看进度。
  3. 能衡量：页面访问、来源、去向 GitHub（借 GitHub 流量统计）、商用授权页访问。
  4. 改内容便宜：官网仓库推到 main、CI 通过后自动上线。
  5. 不丢 v1 的硬指标：中英一一对应、无障碍 0 违规、不用 Cookie、不收集个人信息、移动端性能 ≥ 95。

## 三、讨论与决策

### 讨论：主打什么

- 可选：工作流结果（Codex 按团队需求干活）／数据边界（v1 现状）／产品经理也能问代码。
- **决策（用户 2026-10-05）**：主打「协作、沟通更方便」，其次「管理更方便」。Claude 把三者合成一条主线：协作沟通为主，管理（进度可见）为辅，数据边界作为放心的理由。口号与首屏见 4.1（用户已确认推荐组合）。

### 讨论：访问统计

- v1 需求「默认不接；若接只用不收集个人信息、不需要 Cookie 提示的方案并在页脚说明」，关于页写着「不接统计」。
- **决策（用户 2026-10-05）**：接 Cloudflare Web Analytics。免费、无 Cookie、不收集个人信息，只统计页面访问与来源，不支持自定义事件；去向 GitHub 的点击借 GitHub 仓库的流量统计（Referring sites）看。没选自建 Umami / Plausible：服务器内存紧张，还要多维护一个数据库。

### 讨论：自动部署

- **决策（用户 2026-10-05）**：要，用受限的部署账号。服务器上建一个专用账号，只能往官网目录同步文件、不能登录 shell；密钥放在官网仓库的 GitHub Secrets。密钥泄露的最坏结果是官网内容被改，可以重新部署恢复，碰不到同一台服务器上的其他服务。

### 讨论：演示与体验

- **决策（用户 2026-10-05）**：本次做演示视频和首屏动画；「本机一键体验」要改主仓库，另开需求。

## 四、功能 / 范围

### 4.1 定位与文案

| 项 | 说明 |
|----|------|
| 目标用户 | 已经或准备用 Codex CLI 的 3–30 人研发团队，有产品 / 测试和开发协作；在意代码不上第三方云 |
| 不适合 | 个人单干（直接用 Codex CLI 就够）；想要托管 SaaS；需要管理员、细粒度权限与审批流的组织（产品目前没有） |
| 三个卖点（替换 v1） | ①**沟通在需求旁边**：评论、讨论房间、附件都挂在需求上；共享 Codex 让没代码的人也能问实现。②**进度一眼看清**：看板、概览、我的工作——谁在做、卡在哪、开工后改了什么。③**从需求开工，代码留在本机**：一键拉起本机 Codex，需求随会话带入、结论写回；服务端部署在你们自己的服务器上 |
| 措辞约束 | 「代码留在本机」沿用 v1 审查后的准确说法：模型服务会收到上下文、共享 Agent 的回答会发到房间，首页用一句话加链接到工作原理页说明，不删例外 |

**口号与首屏**（用户 2026-10-05 确认推荐组合）：口号直接做首屏主标题，讲清「做什么」交给小标签和副标题；同一句口号用在首屏、分享卡片、页脚标语、主仓库 README 与 GitHub 仓库描述。

| 位置 | 中文 | English |
|---|---|---|
| 口号 / 主标题 | 速度交给 AI，方向由团队掌舵。 | AI sets the pace. Your team sets the course. |
| 小标签 | 给用 Codex 的研发团队 · 可自己部署 | For teams building with Codex · Self-hosted |

- 被替换的候选（存档）：A「让团队和每个人的 Codex，围着同一份需求协作」、B「需求、讨论和 AI 开发，在一处协作」、C「用 AI 写代码的团队，在这里协作、看进度」，以及「人人用 AI 写代码，团队用速舵对齐」「团队定需求，Codex 写代码」两个方向。

### 4.4 首屏动画与演示视频

| 项 | 说明 |
|----|------|
| 首屏动画 | 15–20 秒循环，基于真实界面录制：需求卡点「开始会话」→ 本机 Codex 改代码、跑测试 → 结论作为评论回到需求。无声；中英各一版；先显示封面图、延迟加载；系统开了「减少动态效果」时只显示封面图 |
| 演示视频 | 1–2 分钟，中英各一版，字幕烧录。脚本：需求看板 → 讨论里 @ 共享 Codex 问实现 → 需求上开始会话 → Codex 读需求改代码跑测试 → 审批与改动 → 结论写回评论 → 概览与我的工作看到变化 |
| 播放 | 视频放在官网自己的服务器上，点击才加载（不预加载、不自动播放有声视频）；不嵌第三方播放器（会带第三方 Cookie）。B 站 / YouTube 另行上传，用于渠道推广 |
| 演示数据 | 复用 README 截图用的中英文演示环境，数据虚构，页面注明 |

**实施记录（R2 / R3，2026-10-05）**

- **与上表的出入：首屏动画没有用真实界面录屏**，改为让现有的「两端」品牌图动起来（需求卡高亮 → 圆点沿交接线落到本机会话 → 会话各行依次出现 → 结果行，约 9 秒一轮，纯 CSS，只动 transform / opacity）。理由：首屏宽度下真实界面的字看不清，还要多加载一段视频、拖累首屏性能；真实界面放在演示视频里。系统开了「减少动态效果」时显示完成后的静态画面，离开视口时暂停。
- **演示视频**：中英各一版，约 1.5 分钟，H.264 1920×1200，各约 3 MB，放在官网 `public/video/`。用演示环境实录：讨论里 @ 共享的 Codex 问实现（真实只读回答）→ 从需求开工 → Codex 改代码、跑测试（真实模型回合）→ 第一次审批 → 完成摘要与改动 → 让 Codex 发评论、确认后发出 → 需求页 → 我的工作 → 片尾口号。Codex 干活的部分加速、中间几分钟剪掉，画面字幕写明「已加速」；字幕与指针画在页面上（不是后期叠加）。本机主机名在录制时替换为「MacBook Pro」，只改显示、不改数据。
- **播放**：首屏主按钮与「开始使用」第一张卡打开同一个原生对话框，点开才设置视频地址与封面（点击前不下载）；无 JavaScript 时就是 MP4 链接。按钮文字按实际时长写成「看 1.5 分钟演示 / Watch the 1.5-minute demo」（原定「2 分钟」）。

## 九、验收

| 项 | 标准 |
|----|------|
| 双语 | `check-content` 通过，中英页面与区块一一对应 |
| 性能与无障碍 | 全站移动端 Lighthouse 性能 ≥ 95，无障碍 / 最佳实践 / SEO 100；axe 0 违规；320–1440 宽度无横向溢出 |
| 隐私 | 页面不写 Cookie；除 Cloudflare 统计脚本外不请求第三方资源；视频点击前不下载 |
| 首页 | 首屏不出现「没有管理员」、Node 版本等顾虑文字；这些在私有部署页能找到 |
| 自动部署 | 推到 main 后 10 分钟内线上更新；部署密钥登录 shell、写官网目录以外的位置都失败 |
| 统计 | Cloudflare 后台能看到访问与来源 |

## Claude 解读

主线从「代码放在哪」换成「团队怎么协作、怎么看进度」，数据边界留作信任理由。先做不依赖定位的运营基础（自动部署、RSS、导航），定位与首页文案等用户选定标题后动手；视频与动画依赖能跑模型的演示环境。
