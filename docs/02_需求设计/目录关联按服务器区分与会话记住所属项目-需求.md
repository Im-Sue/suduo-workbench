# 本机目录关联按服务器区分、会话记住所属项目

> 一句话：换了云端服务器或改了目录关联以后，旧关联不再占着目录，旧会话也不会被算到别的项目下；目录已被别的项目用着时，说清是哪个项目，由用户决定。｜最后更新：2026-10-06
>
> 技术设计：[目录关联按服务器区分与会话记住所属项目-技术设计](../03_开发计划/目录关联按服务器区分与会话记住所属项目-技术设计.md)

---

## 需求描述

**事件**：用户把本机客户端的需求服务地址从本机联调服务器（`127.0.0.1:19090`）换成 `https://cloud.suduo.dev`，在线上新建项目「咔吧」，给它选本机目录 `/Volumes/Sue-SSD/code/web2/kaba` 时被拦下：「该本机工作目录已映射给另一个远程项目」。占着这个目录的，是联调服务器上同名的「咔吧」（2026-09-30 建的关联）。这个项目在新服务器上根本看不到。

查下来是三处问题叠加：

1. **关联不区分服务器。** 关联表只记远程项目 ID。换了服务器，旧服务器的关联原样留着，继续占着目录。
2. **提示不说是谁，也没有出路。** 不说是哪个项目占着，也不给处理办法，不符合 ADR-0004「告知谁改了什么 + 给选项」。
3. **旧服务器的关联在界面上解不掉。** 解除关联前要先向当前服务器查这个项目，查不到就失败。

**根源**：「一个目录只能关联一个项目」这条限制有它的理由。项目会话（不是从需求或房间开的会话）自己不记得属于哪个项目，靠「目录 → 关联」反查出来。如果一个目录对应两个项目，会话的归属就说不清了：会话会同时出现在两个项目下，会话里的 SuDuo 工具（查需求、写评论、改状态）也可能写进另一个项目。需求会话和房间任务会话在建的时候就记下了所属项目，没有这个问题。

所以只修上面三处还不够。如果关联按服务器区分，项目会话却仍靠反查，那么换服务器以后，同一目录里以前开的会话会被算到新服务器的项目下，工具也会去操作新项目。项目会话也要和另外两种会话一样，在建的时候就记住所属项目。

## 原话（verbatim）

> （截图：「选择本机代码目录」对话框，项目「咔吧」，选中目录 kaba，红字「该本机工作目录已映射给另一个远程项目」）

> 之前的数据需要清理掉。确保这次使用是全新的
> 产品层面你的逻辑是对的。推进

本机旧数据已在 2026-10-06 清理完（见第六节），不属于本需求的产品改动。

## 二、目标

- 换服务器以后，旧服务器的关联不影响新服务器上的任何操作；换回去时原样恢复。
- 会话属于哪个项目，建会话时就定下来，之后改关联、换服务器都不变。
- 目录已关联给别的项目时，告诉用户是哪个项目，由用户决定。
- 任何关联都能在本机解除，不需要服务器配合。

---

## 三、讨论与决策

### 决策点 D1：同一服务器上，一个目录能不能给两个项目共用（已定：乙）

用户 2026-10-06 选定：

> 乙（推荐）：允许共用，改为告知。 选目录时提示「这个目录也关联给了「X」」，不拦保存，去掉这个拒绝。也能支持一个仓库对应前端、后端两个项目这类情况，改动更小。

分析过程：

做了第 4.2 节（会话记住所属项目）以后，会话归属不再依赖目录，「一个目录只能关联一个项目」原有的理由就不成立了。按 ADR-0004 的判据过一遍：

- 拿掉这条限制，最坏结果是：两个项目的会话在同一个目录里运行。这是用户自己选的。
- 人能不能自己恢复：能，随时解除其中一个关联即可。
- 是否碰两条红线：不涉及不可逆的字节损失，也不涉及不可逆的对外副作用（会话归属已经固定，工具不会写错项目）。

| 方案 | 做法 | 取舍 |
|------|------|------|
| 甲：保留一对一 | 保存时被拦，说出占用的项目名，给「改为关联到本项目」（原项目的关联解除，原项目已有的会话仍属原项目） | 用户上一轮认可的就是这个做法；但仍保留一个 409 拒绝，四个保存入口（开会话对话框、项目设置、设置 → 工作区、我的工作）都要加冲突处理 |
| **乙：允许共用，改为告知（推荐）** | 选目录时提示「这个目录也关联给了「X」」，保存不拦；想换就去解除原项目的关联 | 符合 ADR-0004；能支持一个仓库对应多个项目（比如前端、后端分成两个项目）；改动更小 |

推荐乙，因为限制的理由消失后，ADR-0004 不允许保留这个拒绝。用户选定乙。

### 讨论：存量数据怎么办

- **旧关联没有服务器地址**：升级时记为当前配置的服务器地址。绝大多数人没换过服务器，这样处理是对的。换过服务器又没清理的，旧关联会被算到当前服务器上，但第 4.4 节保证它能解除；它也不再挡着别的项目用这个目录。
- **存量项目会话**：升级时按当前关联补记所属项目，结果和现在界面上看到的归属一致。没有关联的普通会话保持「不属于任何项目」。

## 四、功能 / 范围

### 4.1 关联按服务器区分

- 每条关联记下建立时连着的服务器地址。
- 设置 → 工作区的关联列表、目录选择里的「最近使用」、我的工作里的「目录失效」提醒、关联数量，都只看当前服务器的关联。
- 换回原来的服务器，原来的关联自动生效，不用重新选目录。

### 4.2 会话记住所属项目

- 项目会话在建的时候记下所属项目，和需求会话、房间任务会话一样。
- 会话列表按项目筛选、会话页显示的所属项目、会话里的 SuDuo 工具，都按会话记下的项目来，不再按目录反查。
- 改了关联或换了服务器以后，旧会话仍属原项目，不会出现在别的项目下，工具也不会去操作别的项目。
- 某个项目的会话列表（开会话对话框里的「已有会话」）按归属列出。以前是列出「当前关联目录里的所有会话」，现在项目换过目录的话，以前目录里的会话也能列出来。

### 4.3 目录已被其他项目使用时

- 选目录时，在目录状态那一行（现在显示「可以读写，但不是 Git 仓库」的位置）加一条提示：「这个目录也关联给了「X」，两个项目的会话都会在这里运行」。不拦保存。X 是当前服务器上看得到的项目名，看不到时写「另一个项目」。

### 4.4 解除关联只动本机

- 解除关联不再向服务器查这个项目。项目已删除、没有权限、离线时都能解除。

## 五、业务规则

| 编号 | 规则 | 说明 |
|------|------|------|
| R1 | 关联按「服务器地址 + 远程项目」记录；只有当前服务器的关联参与列表、最近使用、失效提醒和冲突判断 | 服务器地址以规范化后的地址（协议 + 主机 + 端口）为准 |
| R2 | 会话的所属项目在创建时确定并保存，之后不随关联或服务器变化 | 需求会话、房间任务会话沿用现状 |
| R3 | 同一目录可关联多个项目，选目录时告知已关联的其他项目，不拦保存 | D1 已定乙；去掉原来的目录冲突 409 |
| R4 | 解除关联是纯本机操作，不依赖服务器 | |
| R5 | 解除或更改关联，不删除、不移动任何会话、材料和目录内容 | 沿用现状 |
| R6 | 升级时存量关联记为当前服务器；存量项目会话按当前关联补记所属项目 | 一次性迁移 |

## 六、边界 / 不做项

- 不做跨服务器搬迁，比如把旧服务器项目的关联自动转给新服务器上的同名项目。
- 不识别「同一台服务器的不同地址写法」：`localhost` 和 `127.0.0.1` 会被当成两台服务器。
- 不改云端，不改需求会话、房间任务会话现有的归属方式。
- 「全部会话」列表不按服务器过滤：换服务器以后，旧服务器的会话仍会出现在列表里，所属项目显示为看不到的项目。需要按服务器隔离时另开需求。
- **本机旧数据清理（2026-10-06 已完成，不是产品改动）**：主联调栈的本机库、基线、附件、日志和旧的 Codex 线程，都已整体移到 `Dev/tmp/suduo/backup-before-fresh-20261006/`。保留了 cloud.suduo.dev 的登录、偏好设置和 Codex 模型配置；kaba 目录里遗留的空 `.suduo/` 已删除。本机联调云端（19090）的数据没动。

## 十三、风险

- **迁移补记归属**：存量项目会话按当前关联补记。现在的界面本来就是按当前关联反查的，补记结果和用户现在看到的一致，不会比现状更差。
- **回归面**：会话上下文（工具、重建线程）、会话列表、开会话流程、房间任务都要回归。

## Claude 解读

用户遇到的报错，表面上是旧服务器的关联没清，根子在于项目会话不记得自己属于哪个项目，只能靠目录反查，所以才需要「一个目录一个项目」。让会话记住归属是根治；在这之上，关联按服务器区分、解除不依赖服务器，再按 ADR-0004 把冲突从拒绝改成告知。

## 保真差异

- 原话认可的三点里，第一点（关联带服务器地址）和第三点（解除不依赖服务器）原样落实。第二点（冲突时说出项目名、给「改为关联到当前项目」）按 D1 乙调整：不再拦，改为选目录时说出已关联的项目名，也就不需要「改为关联」按钮。
- 主动新增 R2「会话记住所属项目」：
  - 仲裁者是谁：用户。在哪个项目下开会话，会话就属于哪个项目，不引入拒绝。
  - 拿掉它最坏结果：只做关联按服务器区分的话，换服务器或改关联以后，旧会话会被算到别的项目下，会话工具可能对错误的项目写评论、改状态。这是对外副作用，评论写进去就删不掉。
  - 人能否恢复：难。用户不容易察觉会话已经换了归属。
- 主动新增 R6 存量迁移规则：一次性补记，不引入拒绝。
- 本需求不引入新的拒绝式守卫，还去掉了现有的一个（目录冲突 409）。
