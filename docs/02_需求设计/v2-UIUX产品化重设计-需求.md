# SuDuo V2 UI/UX 产品化重设计 需求设计

> 一句话：把 SuDuo 从"功能都在、但像内部调试台"的界面，重做成一套有统一设计语言、亮暗双主题、每个状态都讲人话的团队产品。｜最后更新：2026-10-01
>
> 技术方案：[`v2-UIUX产品化重设计-技术设计.md`](../03_开发计划/v2-UIUX产品化重设计-技术设计.md) ｜ 视觉原型：[SuDuo 界面重设计画布](https://claude.ai/artifact/JWsNwifyiN56kgNAonTr4W)（9 块画板，可交互）｜ 决策：ADR-0006

## 需求描述

V2 的业务链路（共享需求 → 本机 Codex 会话）已经跑通，但界面是多轮需求逐片叠出来的：同一件事有三套按钮、三套弹窗、两套图标；空态和错误没有样式；正文 12px 靠整页缩放补救；BFF、observed、基线、UUID 这类实现词直接摆给用户看。本需求从产品和设计的角度重新设计整套界面，包括信息架构、设计语言（亮 / 暗）、每个页面的展示与交互、加载与反馈过程，并确定配套的前端技术栈与布局框架。

## 原话（verbatim）

> "我现在觉得 整个产品的 ui&ux设计非常不够产品化，你从产品、设计师设计的角度重新设计整套 系统的界面的 ui&ux，支持亮色和暗色两个色系。完整的展示、交互、过程。梳理一下我们应该用什么技术栈、什么常见的ui框架、什么布局框架，优化每个界面、按钮、加载、交互的逻辑和设计。你完整的规划和设计一下。"
>
> "过往的约束之具有一点参考意义不作为本次升级重构的核心意见，一切以你对项目的理解、发展和设计规划为主"

## 二、背景与目标

### 现状（2026-09-29 四路界面审计摘要）

| 维度 | 主要问题 |
|---|---|
| 体系 | 按钮三套（`.btn` 34 处 / 裸 button 97 处 / `<Button>` 75 处）、弹窗三套、图标两套、原生 select 14 处；字号令牌与 Tailwind 冲突，任意值写法 280 处 |
| 主题 | 默认写死暗色，"跟随系统"永远不是默认；亮色变量复制两份；状态色有硬编码 hex |
| 反馈 | 空态 / 区域错误 / 确认框是无样式的裸元素；加载时先闪空态或闪错误；首屏设置读取失败会永远停在"正在加载" |
| 文案 | 界面上出现 BFF、observed 目录、不纳入基线、realpath、R/W/X、SHA-256、service tier、枚举原值、UUID 前缀、环境变量名 |
| 需求 | 找需求只能肉眼扫看板；卡片只有标题；空列巨型空态；详情单栏长滚动、同屏 3 个主按钮；上传一失败就死锁；"开始对话"可连点出多个会话 |
| 会话 | 四栏挤压，打开 diff 后对话区只剩约 300px；同一回合多段回复会互相覆盖（缺陷）；运行错误被静默吞掉（缺陷）；配置告警插进对话；模型切换改的是全局配置却放在会话输入框 |
| 设置 | 无首启引导；六组设置一行一卡、密度低；测试结果不分成败；代理后端已做、界面没入口 |

### 目标

- **目标 1 · 一套设计语言**：统一令牌（颜色、字体、间距、圆角、阴影、动效）与组件，全站只剩一套按钮、一套弹窗、一套图标。
- **目标 2 · 亮暗对等**：亮色、暗色、跟随系统三种模式，默认跟随系统；两套主题同等打磨，对比度达到 WCAG AA。
- **目标 3 · 说用户的话**：界面不出现实现词汇；对象用编号和名字指代，时间用相对时间。
- **目标 4 · 过程可见、可控、可恢复**：任何异步动作都有明确的进行中、成功、失败表现；AI 的工作过程可一眼看清、随时可停。
- **目标 5 · 效率**：找需求有搜索和筛选，高频操作有快捷键和命令面板，常用路径点击数减少。
- **目标 6 · 首次可用**：新成员从打开到发出第一条会话消息，有一条被引导的路径。

### 用户与主场景

| 角色 | 主场景 | 本次设计的抓手 |
|---|---|---|
| 产品 | 建需求、传材料、发布确认版、看进展 | 快速新建、拖拽上传、产物发布、活动时间线、概览 |
| 开发 | 找到要做的需求、在本机开会话、盯住 AI 干活、审改动 | 我的工作、搜索、一键开会话（含目录选择）、过程时间线、审批、改动审阅 |
| 测试 | 看需求当前状态与验收材料、评论 | 列表视图筛选、活动时间线、评论 |

## 三、讨论与决策

| 决策点 | 结论 | 理由 |
|---|---|---|
| 实施授权 | 用户 2026-09-29 认可全部规划，授权 Claude 全权分阶段实施（串行或并行；含分支提交与合并到本地 main，不推送远端） | 用户原话："你的所有的规划我都认可，你可以全权负责然后所有的规划都逐步 串行或者并行的实施" |
| 旧界面约束 | 降为参考（ADR-0006） | 用户原话；审计显示问题出在约束本身 |
| 组件体系 | 继续 Radix + 自有组件源码（shadcn 方式），不换成套组件库 | 见技术设计 §二 |
| 导航 | 去掉全局顶栏，左侧栏承载项目切换、主导航、搜索入口 | 顶栏只放了品牌和原生 select，却占掉整条纵向空间；项目是导航的上下文，应与导航在一起 |
| 需求速览 | 看板 / 列表点卡片 → 右侧速览面板；需要时再进完整详情页 | 浏览多个需求时不丢失看板上下文 |
| 会话过程 | 文字与工具步骤按时间交错；连续步骤聚合成一行摘要，默认折叠 | 用户要的是"它在干什么、干到哪"，不是每条命令原文 |
| 审批 | 固定在输入框上方，不随消息流滚走 | 审批是阻塞点，必须始终在视线里 |
| 模型 / 审批档 | 放到输入框底栏，按会话生效 | 现状改的是全局配置，与所在位置语义不符 |
| 实时 | 就地更新 + 1.5 秒高亮 + 活动时间线留痕，不弹冲突窗 | 延续用户 2026-09-05 "不告知、不拦截" |
| 界面缩放 | 取消 CSS zoom，改为"舒适 / 紧凑"两档密度 + 正文 14px | zoom 会让浮层错位；12px 正文本身偏小 |
| 停滞口径 | 按各状态的节奏判断（草稿、暂缓也算，但门槛更长），不再让人选统一天数 | 开发中 3 天没动和草稿 3 天没动不是一回事；统一天数要么漏掉卡住的开发、要么被草稿刷屏。用户 2026-09-29 授权按项目定位决定 |
| 「我负责的（或我创建的）」 | 列我负责的 + 我提的、还没人负责的（未完成） | 我提了但没人接的需求需要我去找人或自己接；已经交给别人负责的归对方，不重复提醒。同上授权 |
| 新评论的已读状态 | 按账号记在需求服务（个人状态，不参与任何写入校验）；只记到界面上真的显示出来的最新一条、只往前走；从没打开过的只算最近 7 天；确认版发布说明不算评论 | 换电脑也一致；避免老需求一上来全是「新评论」；数字与用户在「评论」里看到的对得上 |

## 四、功能 / 范围

### 4.1 全局：外壳、导航与主题

| 项 | 说明 |
|---|---|
| 左侧栏 | 展开 240px / 收起 56px（⌘\）。自上而下：项目切换器（可搜索、含新建 / 管理项目）→ 搜索（⌘K）→ 我的工作 / 需求 / 会话 / 概览 → 底部设置、账号菜单。会话项显示运行中数量，我的工作显示待处理数量 |
| 页面头 | 每页统一：面包屑、标题、页面级操作（最多一个主按钮）、视图切换 |
| 命令面板 | ⌘K：搜索需求（按编号或标题）、会话、项目；执行动作（新建需求、新建会话、切换主题、打开设置） |
| 主题 | 亮 / 暗 / 跟随系统，默认跟随系统；账号菜单可一键切换；首屏无闪烁 |
| 密度 | 舒适（默认，控件 32px、行高 36px）/ 紧凑（28px / 32px） |
| 连接状态 | 需求服务断开时，内容区顶部出现横幅"与需求服务的连接已断开，正在重连…"并带立即重试；恢复后自动消失 |
| 快捷键 | ⌘K 命令面板、C 新建需求、/ 搜索、⌘\ 侧栏、⌘J 右侧面板、Esc 关闭 / 停止、? 快捷键一览 |

### 4.2 首次使用引导

全屏向导，按顺序：**连接需求服务**（地址 + 测试连接，说明向谁要地址）→ **登录 / 注册** → **检查本机环境**（Codex CLI 是否可用、模型服务是否配置、需不需要代理，逐项给出"去配置"）→ **选择项目并关联代码目录**（目录选择器）→ **完成**。可选项可跳过；未完成项在"我的工作"顶部以清单形式保留，全部完成后消失。

### 4.3 我的工作（默认落地页）

| 区块 | 内容 |
|---|---|
| 需要你处理 | 按紧急程度：等你确认的会话 > 上一轮失败的会话 > 指派给我且有新评论的需求 > 开工后需求有变化的会话 > 指派给我且按节奏停滞较久的需求 > 代码目录失效；每条带直接操作。侧栏「我的工作」旁的数字与这里一致 |
| 进行中的会话 | 卡片显示实时状态、关联需求编号；在跑时显示已用时间与当前在做的一步（如「运行命令：npm test」），否则显示最后一句话 |
| 我的需求 | 我负责的需求 + 我提的、还没人负责的需求（未完成的；标「我提的 · 还没人负责」）+ 我有会话在做的需求，按状态分组，可切换"全部项目 / 当前项目"（写进地址 `?scope=`） |
| 最近动态 | 与我相关的需求变化 |

「新评论」= 别人发的、我还没看到的评论（确认版的发布说明并在「确认版」条目里，不算评论，与时间线「评论」筛选看到的一致）：需求详情在前台、评论真的显示出来才算看过（详情开在后台、评论被筛掉都不算），已读位置记到看到的最新一条、只往前走；已读位置按账号记在需求服务上（换电脑也一致），从没看过的需求只往回算最近 7 天。

后台刷新不转圈、不禁用按钮；各区块独立加载、独立失败、独立重试。

### 4.4 需求

| 项 | 说明 |
|---|---|
| 看板视图 | 7 列（草稿、梳理中、待开发、开发中、测试中、已完成、暂缓），列头为状态图标 + 名称 + 数量 + "+"（在该状态下新建）；空列只显示淡色"暂无"；支持拖拽和键盘移动（选中卡片后按数字键或 ⇧→ 改状态） |
| 列表视图 | 按状态分组的表格：编号、标题、状态、负责人、附件 / 评论 / 会话数、更新时间；可排序，行可多选批量改状态 |
| 卡片 | 状态图标、编号、标题（最多 2 行）、摘要首行、附件 / 评论 / 本机会话计数、负责人头像、相对更新时间 |
| 搜索与筛选 | 关键词（标题 / 编号）、状态、负责人、创建人、更新时间、"有本机会话"；筛选写进 URL，可分享、可收藏 |
| 速览面板 | 右侧 480px：标题、状态、负责人、摘要、材料数、最近 3 条活动、本机会话；主按钮"开始会话"；"打开完整页"；↑↓ 切换上一条 / 下一条 |
| 新建需求 | 对话框：标题（必填）、状态（默认草稿或来源列）、负责人、描述（Markdown，可空）、材料（可拖入）；⌘Enter 提交，"继续新建下一条"开关 |
| 详情页 | 两栏：主栏为标题（原地编辑）→ 描述（Markdown 渲染，点击编辑）→ 材料与产物 → 活动；右栏为属性（状态、负责人、编号、创建人与时间、所属项目）、代码目录、本机会话列表 + 主按钮"开始会话" |
| 材料与产物 | 拖拽 / 粘贴 / 选择上传；每个文件一行进度，失败的单独重试，不阻塞其他文件；图片、PDF、文本、Markdown 可在线预览；"发布确认版"对话框可全选、写版本说明，版本列表显示说明、发布人、与上一版的文件差异 |
| 活动 | 评论与变更记录合并为一条时间线：谁、何时、把什么从 A 改成 B；评论支持 Markdown 与 @ 成员；下载行为不进时间线 |
| 实时 | 他人改动就地更新，被改动的卡片或字段高亮 1.5 秒，时间线追加一条；不弹窗、不打断编辑 |
| 开始会话 | 点击后按钮进入加载态、不可重复点；未关联目录时先在同一对话框中选目录；然后显示分步进度（准备需求材料 → 下载附件 2/3 → 创建会话），完成后进入会话；已有会话时询问"继续上次"或"新开一个" |

### 4.5 会话

| 项 | 说明 |
|---|---|
| 布局 | 三栏可拖拽：会话列表（默认 280px）｜对话（内容最宽 760px 居中）｜检查面板（默认 400px，可收起，⌘J）。宽度记忆；窗口小于 1280px 时检查面板变为浮层 |
| 会话列表 | 只列当前项目的会话（用户 2026-10-01 改口径，原为跨本机所有项目）：需求会话按需求所属项目、房间任务按房间所属项目、其余按代码目录关联归属，不属于任何项目的会话不在列表里（链接仍可直达）；左上角换项目时列表跟着换，打开着的上一个项目的会话收起；从我的工作等处打开别的项目的会话时，当前项目跟到该会话所属项目。侧栏「会话」旁的数字同样只算当前项目，跨项目的「等你确认 / 上一轮失败」由我的工作汇总。筛选：全部 / 运行中 / 需要我；按今天 / 昨天 / 更早分组；每行：状态图标、标题、关联需求编号、最后活动时间、最后一句预览；"…"菜单里有重命名（原地）、归档、删除（二次确认） |
| 会话头 | 标题（原地重命名）、关联需求（点开速览）、代码目录与分支、状态 |
| 对话流 | 用户消息（图片缩略图、@ 文件标签）；助手回合 = 文字段落与"步骤组"按时间交错。步骤组聚合为一行摘要（"查看了 6 个文件 · 运行了 2 条命令 · 18 秒"），展开后每步显示图标、标题、耗时、退出码，命令输出用终端样式；计划（待办清单）实时勾选；文件改动显示为改动卡片（+42 −8），点击在检查面板打开 diff |
| 回合结束 | 摘要行："完成 · 用时 2 分 14 秒 · 修改 3 个文件 · 运行 5 条命令"，带"查看改动""回到开始前" |
| 运行中 | 发送后立即出现"思考中"；底部实时显示当前步骤与计时；停止按钮（Esc）→ "正在停止…" → "已停止"；等待审批时显示"等你确认"，不再转圈 |
| 审批 | 固定在输入框上方的卡片："Codex 想运行 `pnpm test`"或"Codex 想修改 3 个文件（查看 diff）"；批准（⏎）、拒绝（Esc）、"本会话都允许"；多个审批时逐个处理并显示 1/3 |
| 系统提示 | 模型配置类告警收进会话头的提示图标，不进对话流 |
| 错误 | 回合失败显示原因和"重试"；连接中断显示"已断开，正在重连" |
| 输入框 | 多行自动增高；`@` 插入文件标签，`/` 选择 skill（可多选）和命令；支持图片及常见文本类附件；底栏：附件、模型与推理强度（本会话）、审批档（本会话）、上下文用量环、发送 / 停止；运行中输入会进入"排队"，可编辑、可移除；↑ 取回上一条 |
| 检查面板 | 标签页：**改动**（文件列表 + diff，可逐文件撤销）、**需求**（开工时版本 vs 现在，有变化时提示并可查看差异；附件拉取）、**环境**（目录、分支、检查点时间线与恢复）、**文件**（树 + 查看器） |
| 完成通知 | 会话在后台完成或需要审批时：侧栏计数变化、浏览器标题前缀、可选系统通知 |

### 4.6 项目概览

| 区块 | 内容 |
|---|---|
| 状态分布 | 7 个状态的数量（图标 + 数字），点击跳到带筛选的需求列表 |
| 流转趋势 | 近 7 / 30 天每天进入各状态的数量，带坐标轴与日期；时间范围写进地址（`?range=`） |
| 停滞需求 | 按各状态的节奏判断，不用统一天数：开发中 / 测试中 3 天、梳理中 / 待开发 7 天、草稿 14 天、暂缓 30 天没有变化即列出（「该推进了」）；开发中 / 测试中 7 天、梳理中 / 待开发 14 天、草稿 30 天为「停滞较久」，排在前面；已完成不算 |
| 最近动态 | 时间线，限高可展开 |

### 4.7 设置

| 项 | 说明 |
|---|---|
| 结构 | 左侧分组导航（带图标、异常红点）+ 设置搜索；分组：外观、账号、需求服务、代码目录、模型服务、执行与安全、Skills、MCP 服务、网络代理、诊断、关于 |

## 五、设计原则与规则

| # | 原则 | 落地规则 |
|---|---|---|
| D1 | 说用户的话 | 按 §5.1 词表替换；对象用编号 / 名字；ID、哈希、环境变量、枚举值只在"诊断 / 复制详情"里出现 |
| D2 | 一处一个主动作 | 每个页面、面板、对话框最多一个主按钮；危险操作用危险样式并二次确认，默认焦点在"取消" |
| D3 | 状态总是可见 | 加载不闪空态；空态和错误态分开；后台刷新保留旧数据；失败就近显示、给原因和下一步 |
| D4 | 过程透明但安静 | AI 过程默认摘要化；需要人时（审批、失败）抬到最前；配置类提示不进对话 |
| D5 | 实时但不打断 | 他人改动就地更新 + 轻高亮 + 留痕，不弹窗（用户 2026-09-05 决策） |
| D6 | 键盘可达 | 所有操作可用键盘完成；焦点可见；命令面板覆盖高频动作 |
| D7 | 亮暗对等 | 两套主题都达到 AA 对比度；状态区分同时靠形状，不只靠颜色 |

## 六、边界 / 不做项

- 不改变业务链路与数据归属：共享的是需求，私有的是代码和对话。
- 不做移动端专门形态；小于 1024px 只保证可用（单栏 + 浮层）。
- 不做多语言，界面语言为中文。（2026-10-02 起由[产品中英双语](产品中英双语-需求.md)需求覆盖）
- 不做在线协同编辑（多人同时编辑同一段描述的实时合并）。
- 不做通知中心与消息推送服务；完成 / 审批提醒只在本机浏览器内。
- 不做需求优先级、标签、截止日期、父子关系（留待后续需求）。
