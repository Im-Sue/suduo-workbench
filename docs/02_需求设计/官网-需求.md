# SuDuo 官网

> 一句话：一个中英双语的静态官网，向国内和海外团队讲清 SuDuo 是什么、怎么部署、怎么商用登记；代码放在新开的独立仓库。｜最后更新：2026-10-02
>
> 同批需求：[开源与商用授权](开源与商用授权-需求.md)、[云端私有化部署](云端私有化部署-需求.md)、[客户端源码运行](客户端源码运行-需求.md)、[产品中英双语](产品中英双语-需求.md)。视觉方案：[SuDuo 品牌标志与视觉方案（画布）](https://claude.ai/artifact/CaXGurbSRLXdWkJNRsC2aU)。

---

## 需求描述

SuDuo 不提供中心化服务，官网不是注册入口，而是：

1. **讲清产品**：需求在团队、代码在本机；从需求一键开工；部署在使用方自己手里。
2. **引导上手**：服务端怎么部署、客户端怎么跑，链到仓库里的中英文档。
3. **讲清许可**：个人与学习免费，企业使用需登记，怎么登记。
4. **品牌门面**：按已定的视觉方案（「接力 S」标志、靛蓝 + 青绿、IBM Plex Sans + 思源黑体）。

## 二、背景与目标

**目标对齐**：访客分两类，一类是在找工具的团队负责人，一类是要动手部署的工程师。前者在首屏十秒内看懂 SuDuo 解决什么问题、和普通 AI 编码工具有什么不同（团队需求与本机 AI 会话相连，代码不出本机）；后者两次点击内找到部署文档和 GitHub。中文访客默认看中文，英文访客能切到英文，两种语言内容一一对应。网站是纯静态的，没有后台、没有账号。

**模拟示例**：

1. 海外工程师从搜索结果进入 `/en/`，首屏标题是 “Requirements with your team. Code on your machine.”。
2. 他往下读「工作原理」：一张两端示意图，团队服务器上是需求和讨论，每个人电脑上是代码和 Codex 会话，中间由 SuDuo 连接。
3. 他点「Self-hosting」，看到三步摘要，以及「完整文档在 GitHub」的链接。
4. 他点导航里的「Commercial use」，读到「企业可以直接使用，开始使用后 30 天内登记，目前免费」和登记邮箱。

- **背景**：没有任何对外页面；标志与视觉已在画布上定稿方向；域名与中文品牌名待定。
- **目标**：
  1. 中英双语、内容一一对应。
  2. 首屏讲清定位，两次点击内到达部署文档与 GitHub。
  3. 国内外都能正常访问，手机上体验完整。
  4. 维护简单：内容是 Markdown，改文案不需要动代码。

## 三、讨论与决策

### 讨论：代码放哪

- **决策（用户 2026-10-02）**：新开独立仓库，建议命名 `suduo-website`。上线前保持私有，上线时与主仓库同步公开。官网与产品的发布节奏、协作者都可以分开。

### 讨论：技术形态

- **决策（Claude 推荐）**：静态站点生成器（倾向 Astro），内容用 Markdown，构建产物是纯静态文件，可以放在任何静态托管或 CDN 上。不需要服务器、数据库、后台。具体选型在技术方案里定。

### 讨论：语言路由

- **决策**：中文在 `/`，英文在 `/en/`。页面右上角可切换，切换后停在对应页面。首次访问不强制跳转（避免搜索引擎收录错乱），浏览器语言是英文时顶部给一条「Switch to English」提示。

### 讨论：要不要定价页

- **决策**：不做。收费未定（用户：「收不收费再说」），用「商用授权」页代替。

### 讨论：托管与访问

- 国内访问海外托管的站点可能慢或不稳；国内托管又需要 ICP 备案（周期以周计）。
- **决策**：域名定了再定托管。技术上保持纯静态，国内、海外两套托管随时都能接。

## 四、功能 / 范围

### 4.1 页面清单（中英各一份）

| 页面 | 内容 |
|----|------|
| 首页 | 首屏（标题、副标题、两个主按钮「部署到你的服务器」「在 GitHub 查看源码」、两端示意图）；三个核心卖点；工作原理简图；适用场景；平台支持；底部行动区 |
| 产品功能 | 需求看板与详情、项目 / 需求讨论房间、共享 Codex、从需求开工的本机会话、审批与文件变更、我的工作与概览；每项配产品截图 |
| 工作原理 | 两端架构图；数据边界（哪些在团队服务器、哪些只在本机）；与「把代码交给云端 AI」类方案的区别 |
| 私有部署 | 服务端三步摘要、系统要求、客户端快速开始摘要，链接到仓库里的完整中英文档 |
| 商用授权 | 许可说明（个人 / 学习 / 公益免费；企业拿起来就能用，开始使用后 30 天内登记）、常见情形判断、登记方式与邮箱、「目前登记免费」；链接到许可证原文与 `COMMERCIAL.md` |
| 更新日志 | 按版本列出变更，与仓库发布标签对应 |
| 关于 / 联系 | 项目简介、联系邮箱、GitHub |
| 404 | 双语 |

### 4.2 全站要求

| 项 | 说明 |
|----|------|
| 视觉 | 严格按视觉方案：「接力 S」标志、色板、字体、图形语言（两端一桥、点阵底纹、交接虚线）；亮暗两套主题，跟随系统 |
| 响应式 | 桌面、平板、手机；手机端首屏参照画布上的手机版示意 |
| 无障碍 | 文字对比度 ≥ 4.5:1，键盘可达，图片有替代文字 |
| 性能 | 首页移动端 Lighthouse 性能、无障碍、SEO 各 ≥ 90；字体按需加载、子集化（思源黑体体积大，要做子集） |
| SEO | 每页 title / description；`hreflang` 标注中英对应页；站点地图；Open Graph 分享卡片（中英各一套，用品牌视觉） |
| 统计 | 默认不接统计；若要接，只用不收集个人信息、不需要 Cookie 提示的方案，并在页脚说明 |
| 商标声明 | 页脚注明 Codex / OpenAI 为其所有者的商标，SuDuo 与其无隶属关系 |

### 4.3 内容维护

| 项 | 说明 |
|----|------|
| 做什么 | 所有文案与更新日志是 Markdown 文件，中英分目录放；新增或修改内容不需要改页面代码。缺少某一语言的译文时构建报错，不悄悄回退 |
| 截图 | 产品截图分中文界面与英文界面两套（依赖[产品中英双语](产品中英双语-需求.md)完成） |

## 六、边界 / 不做项

- 不做账号、登录、在线试用、云端托管版。
- 不做定价与支付。
- 不做在线登记表单（首期邮件）。
- 不做博客与文档站（文档链接到 GitHub；文档站以后视需要再做）。
- 不负责域名购买、备案办理、托管开通（需用户操作，本需求给清单）。

## Claude 解读

一个纯静态、中英对应的产品官网，放在新仓库。它讲清定位与数据边界，把人引到部署文档、GitHub 和商用登记；按已定的视觉方案实现，不做价格、账号和表单。

---

## 歧义点

待用户提供或确认：域名、托管。其余已闭环。

## 保真差异

- 原话「独立设计一套官网」：落实为新开仓库的独立站点，视觉沿用已定方案。
- 主动新增：商用授权页（替代定价页）、无障碍与性能指标、不收集访客信息的统计约束。均不引入拦截行为。
