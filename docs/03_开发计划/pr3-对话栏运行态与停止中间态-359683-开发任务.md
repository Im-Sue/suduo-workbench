## 二、任务分解

### PR3 · 对话栏运行态与停止中间态

#### 任务概述

现在发消息之后，只有页面右上角亮一个「中断」，离你的手最远；点下去到真正停下之间没有任何反馈，还能重复点。这一片把运行态放到输入框旁边：发送按钮旁出现停止控件（两个都可点），输入框上方一行「Codex 正在工作 · 正在执行 pnpm test · 12s」，等审批时整行换成审批提示。点停止立即本地反馈并禁用，收到任一终态（含自然完成）才收口。状态行和顶栏徽章必须说同一句话，所以顶栏判定的两份实现在这一片就统一掉。

对应需求：4.1、4.6、R2、R10；技术设计 §四.3、§四.5（发送按钮 / 状态行 / 顶栏徽章判定 / 计时基准）、§三-4。

#### 任务分解

1. `client/web/src/event-projection/reducer.ts`：`TurnGroup` / `turnMeta` 暴露当前步骤（最后一个 `running` step 的 title）。
2. **计时锚点（实时边界证据）**：`sawStart` 只证明投影见过 `turn.started`，不能证明本页实时见过；而且 SSE 一条连接先回放账本再转实时（`client/server/src/application/event-stream.ts:38`，先 `listRange` 分页回放到 highWater，再排空 `buffered`，再 directLive），仅排除 HTTP 回填路径（`SessionRuntime.tsx:401`）仍会给回放阶段到达的历史 `turn.started` 建锚点。规则：**只有拿到实时边界证据才建锚点，无法证明就不显示时长**。实现（**它是传输控制帧，不是账本事件，不能沿用现有序列化**）：① `event-stream.ts` 在回放循环结束、开始排空 `buffered` 之前，向本连接发一条不入账本、无 seq 的控制帧 `stream.live`；② `open()` 今天的返回类型是 `AsyncIterable<EventEnvelope<string, JsonValue>>`（`event-stream.ts:21` 声明、`:25` 标注），控制帧不是 `EventEnvelope`、没有 `seq`，返回类型须放宽为「账本事件 | 传输控制帧」的判别联合（如 `{ kind: "event", event }` / `{ kind: "control", type: "stream.live" }` 或等价）；③ `formatSseEvent()`（`event-stream.ts:169`）**无条件**输出 `id: String(event.seq)`，控制帧若走它会写出字面量 `id: undefined`，被浏览器存成 Last-Event-ID 并在重连时带回，污染服务端的 `after` 游标——控制帧必须走单独的序列化分支：输出 `event: stream.live` 加一行可派发的 `data:`（如 `{}`），**完全省略 `id:` 行**（既不写 `undefined` 也不写空 id）；账本事件的输出字节保持逐字不变；④ `client/server/src/infrastructure/http/http-server.ts:1411` 的写循环（`await writeWithTimeout(reply.raw, formatSseEvent(event))`）按帧类型分派；加法式，不进 `EventRepository`，不影响其他消费者；`SessionRuntime.tsx` 在订阅处为 `stream.live` 单独 `addEventListener`，置 `liveBoundaryReached=true`（不进 `mergeSessionEvents`、不进缓存、不加入 `EVENT_TYPES` 合并列表）；此后经 `:366` 收到的 `turn.started` 记 `Date.now()` 为本地锚点；边界前（SSE 回放）与 HTTP 回填（`:401`）一律不建。EventSource 重连或重开时边界标志复位，等待新的 `stream.live`。**禁止**用 `Date.now() - event.ts` 阈值判断实时性（跨时钟；`RECOVERY_BANNER_FRESH_MS` 那种用法不得复用到计时）。有锚点才显示时长，没有只显示「运行中」。
3. `client/web/src/components/Composer.tsx`：运行中发送按钮旁并存停止控件（`interrupt-turn` testid 跟控件走）；输入框上方新增状态行（当前步骤 + 已耗时；审批等待时换审批提示 + 跳转）。不做任何队列相关布局。
4. `client/web/src/app/SessionRuntime.tsx`：
   - `stopping` 状态；点停止立即置位 + 禁用；`api.interrupt(sessionId, { turnId })` 传前端投影认定的运行回合（现 L609 不传）；收到该回合任一终态（completed / interrupted / start-failed）收口；迟到的 `turn.interrupt-requested` 不得把已终态回合拉回 stopping；请求失败解除 stopping 并如实报错；目标回合已终态而另有回合在跑 → 告知「刚才那一轮已经结束，现在在跑的是新的一轮」+「停止当前这一轮」按钮，绝不自动中断；顶栏移除中断入口（L608）只留徽章。
   - **统一状态判定**：删除 `runtimeStatus()`（L786），顶栏徽章与状态行都走 `client/web/src/ui/session-status.ts:sessionUiStatus`（允许微调签名）。
   - `stopping` 与计时锚点按 sessionId 清理。
5. `client/server/src/application/interrupt-service.ts`：`alreadyStopped` 分支（L49-76）补写 `turn.interrupted` 前先查账本该回合是否已有终态；`expected active turn id X but found Y`（失配）新纳入「目标已非活跃」幂等语义；`no active turn` 已在 `isTurnGoneError`（L153-163）匹配中——保留并补集成覆盖；两者都不抛 `IndeterminateOperationError`。
6. 单元测试（前端）：用可控的异步中断响应构造「终态事件先到、`turn.interrupt-requested` 后到」，断言停止控件已收口且不被拉回；自然完成收口；请求失败解除锁定；计时三例——首次开页（缓存截断，SSE 回放里带历史 `turn.started`）不出时长、断线重连后回放的运行中回合不出时长、`stream.live` 之后实时到达的 `turn.started` 出时长。服务端三例（**只测生成器产出一次控制帧不够**）：① `event-stream.open()` 回放结束后、实时事件之前恰好发出一条 `stream.live`；② 序列化——`stream.live` 帧不含 `id:` 行，且同一批账本事件序列化后的字节与改动前逐字相同；③ 续传游标——回放 → `stream.live` → 立即断线 → 客户端携 `Last-Event-ID` 重连，断言服务端解析出的 `after` 仍是最后一条**账本事件**的 seq，未被控制帧污染。
7. 集成测试（InterruptService）：**查账本**——已有 `completed` 的回合发中断后账本里没有第二个终态事件；F5 / F6 两种 `-32600` 按幂等处理不抛 `IndeterminateOperationError`。只测错误文案匹配函数不算。
8. `final-interrupt.ts`（L11-13 依赖 `interrupt-turn`）在控件移位后仍绿，前提：`interrupt-turn` 标识唯一、运行中可点击、终态后**隐藏**（不能只改为禁用）；`data-testid-baseline.json` 同片更新并通过 `pnpm testid:check`。

#### 验收标准

- 运行中：发送与停止并存，两者都可点；停止后 0ms 内本地反馈并禁用重复点击
- 状态行与顶栏徽章**状态语义一致**（同一判定函数；状态行可额外附步骤与时长），顶栏能显示「已完成 / 异常」；开页前 / 重连前已在跑的回合（经 SSE 回放或 HTTP 回填得知 start）只显示「运行中」不显示时长，`stream.live` 后实时开始的回合显示时长
- `stream.live` 不入账本、不进缓存、不改既有事件形状；控制帧不带 `id:` 行、账本事件序列化字节与改动前逐字相同；控制帧后断线重连时服务端拿到的 `after` 仍指向最后一条账本事件；`client/codex-protocol` `schema.mjs diff` clean
- 自然完成、被中断、失败三种终态都收口停止控件
- 对已自然完成的回合发中断，账本里 `completed` 不被改写成 `interrupted`
- 反馈时序只引用 `FEEDBACK_TIMING_MS`，不新定义阈值
- 上述单测 / 集成全绿；用 PR1 子集入口跑 `final-interrupt`、`interrupt-and-reopen` 通过；`pnpm testid:check` 通过
