## 二、任务分解

### PR7 · 我的工作台三区块

#### 任务概述
把工作台从占位填成真页面。它回答的是**「我现在该干什么」**，跨项目，不受顶栏项目选择影响。

这一片承载本需求价值最高的一个单点：**首次把「你手上的会话材料已经过期」这件事告诉用户**。在此之前，产品改了需求正文，基于旧材料干活的人是完全无感的。

#### 任务分解

**1. 待我处理** — 三类阻塞项按固定优先级排：**待审批 > 失败回合 > 映射失效**。

  这个顺序不是随意的：待审批是**活的阻塞**（Codex 正停在那儿等人点头，每多等一秒都是纯浪费），失败是已发生待查看，映射失效是潜在的、还没触发的。

  每条都要能一键直达处理现场：待审批和失败回合 → 跳对应会话；映射失效 → 打开映射设置对话框。

**2. 我在做的需求** — 每行：需求标题 + 所属项目 + 当前状态 + 我的会话数与运行态 + **材料过期警示**。

  - 标题 / 所属项目 / 当前状态都来自远程当前值，不是快照值
  - 漂移警示文案：**「需求正文或状态已变更」**，点击进需求详情看当前内容
  - 快照缺失或损坏：显示「快照不可读取」，**不要误报成漂移**
  - **列表必须说明口径**：这里只包含「我从这条需求拉起过会话、且会话仍活跃」的需求。他人指派、我还没开工的需求看不见——这个盲区已知且接受，但用户必须能从界面看懂，否则会误以为自己没活

**3. 我的会话** — 按 `lastActivityAt` 倒序，跨项目。每行：标题 + `purpose` 徽章 + 运行态（运行中 / 待审批 / 失败）+ 所属项目 + 关联需求，点击直达会话。

**4. 刷新机制** — **页面可见时定时轮询（10s）+ 手动刷新按钮**。

  **禁止用 SSE**：本机 `EventBroker` 只支持按单个 `sessionId` 订阅，没有全局事件流；扩展它等于动会话运行时核心，超出本需求边界。轮询必须在页面不可见时停、组件卸载时清理干净，别留定时器泄漏。

**5. 分块降级**（需求 R10）— 三块各自读 envelope 的 `status`。某块 `unavailable` 时**只有那块**显示错误与重试按钮，另两块照常展示。

**6. 空态**（需求 R9）— 无待处理项显示明确的「当前没有需要你处理的事」；本机无会话记录时说明原因（本机私有数据、换电脑或重装后为空）并引导从需求看板拉起会话。

#### 验收标准
- [ ] 三块任一 `unavailable` 时，另两块正常展示，失败块有独立错误与重试
- [ ] 待我处理排序符合 待审批 > 失败回合 > 映射失效；三类各自的跳转都到位
- [ ] 漂移警示：正文或状态变了 → 显示「需求正文或状态已变更」；**只有 version 变了 → 不显示**；快照缺失 → 「快照不可读取」
- [ ] 切换顶栏项目，工作台内容**不变**（跨项目，需求 R7）
- [ ] 轮询在页面隐藏时停止、恢复可见时继续；离开页面后无残留定时器（用 fake timer 测）
- [ ] 手动刷新可用
- [ ] 两种空态文案按 R9 落地
- [ ] 列表上有口径说明，DOM 中可断言到明确文案：**「只显示你拉起过会话、且会话仍活跃的需求」**；他人指派、我还没开工的需求不在此列

#### 边界
- **禁止修改 `RequirementsV2App.tsx` 与 `api/client.ts`**——PR5 已定稿，改了会和 PR6 冲突
- **禁止用 SSE 或扩展 `EventBroker`**
- 不改造会话材料刷新机制——本期只负责把过期信号暴露出来，不负责修它
- 不改会话运行时既有交互
- 不引任何新依赖

## 协商增补

> 来源：batch 前置协商 `job_0b09b882cf21`（slot1_codex，consult 模式）。

### 「无残留定时器」与「DOM 可断言」需真实挂载证据

纯轮询调度模块的 fake-timer 测试只能证明 `dispose()` 自身正确，**不能证明组件在卸载时调用了它**。本片验收须同时给出两层证据：

- 纯模块层：轮询调度模块 + `vi.useFakeTimers()`，覆盖页面隐藏停止、恢复可见继续
- DOM 层：复用 PR5 建立的 jsdom + `react-dom/client` 设施，真实挂载后 `unmount()`，断言 `vi.getTimerCount() === 0` 且继续推进时间不再产生请求；口径说明文案「只显示你拉起过会话、且会话仍活跃的需求」在 DOM 中可断言

**不引入 `@testing-library/react`**；`vitest.config.ts` 由 PR5 改完，本片直接复用，不再改配置——本片与 PR6 因此保持互不依赖。
