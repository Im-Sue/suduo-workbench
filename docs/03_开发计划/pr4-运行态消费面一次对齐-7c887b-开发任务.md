## 二、任务分解

### PR4 · 运行态消费面一次对齐

#### 任务概述

运行态在页面上还有几个消费者各说各话：侧栏状态灯对选中会话也走 10s 轮询（`SessionsRail.tsx:255` 传 `0, 0`）——而且侧栏和运行区在 `SessionsWorkbench.tsx` 里是两个兄弟组件，今天根本没有实时状态回传的通道；模型切换器那句「回合进行中，切换会中断当前工作」没有代码依据；检查点的保存 / 还原在运行中一律禁用。这一片让它们全部跟 PR3 统一后的判定走，并把无依据的话按 PR1 的实测结果改准。

对应需求：4.5、第七章移交项（模型切换器、断线恢复）；技术设计 §四.5、§三-6。

#### 任务分解

1. `client/web/src/app/SessionsWorkbench.tsx`：新增实时通道——`SessionRuntime` 把选中会话的 `running` / `pendingApprovals` / 最终结果（`lastTurnOutcome` 等价物）回传给 `SessionsWorkbench`，再传给 `SessionsRail`；**选中会话以实时值为准，10s 轮询的旧摘要不得把实时的「空闲 / 已完成」覆盖回「运行中」**。
2. `client/web/src/components/sessions/SessionsRail.tsx`（L255）：选中会话使用上述实时值。
3. `client/web/src/components/ModelSwitcher.tsx`（L122）：按 PR1 回执里的实测结果改文案；实测与代码判读（`updateModelProvider → configBatchWrite({reloadUserConfig:true})`，全链路无 interrupt / turn 操作）冲突时以实测为准；**不得凭空换成另一句未经验证的话**。
4. `client/web/src/components/EnvPanel.tsx`：保存检查点（L133）去掉运行中拒绝，改为告知后继续「这一轮还在跑，现在存的快照可能不包含正在写入的改动」；还原到检查点（L177）保留禁用，tooltip 改为说明原因（会覆盖 agent 正在写的文件，属不可逆字节损失红线）。
5. `client/web/src/event-projection/cache.ts`：删除无人调用的 `cachedRunningCount`（L144）。
6. 断线恢复 / 历史补齐后：无有效本地锚点时不显示时长（复用 PR3 规则，本片验证）。
7. `data-testid-baseline.json` 同片更新并通过 `pnpm testid:check`。

#### 验收标准

- 侧栏选中会话状态灯与顶栏徽章同步变化，不等 10s 轮询；回合结束后侧栏不会被下一次轮询短暂改回「运行中」
- 模型切换器文案与 PR1 实测结果一致，回执引用该实测记录
- 运行中可保存检查点并看到告知文案；还原按钮禁用且 tooltip 说明原因
- `cachedRunningCount` 删除后无引用，构建通过
- 无有效本地锚点（断线重连、开页前已在跑、历史补齐）时状态行显示「运行中」且无时长
- ADR-0004 自查：本片拿掉一处拒绝（保存），保留一处拒绝（还原，红线），不新增
- 用 PR1 子集入口跑 `sessions-rail`、`changes-and-diff` 通过；`pnpm testid:check` 通过

#### 边界

不引入新判定函数（唯一来源已在 PR3 定）；不改 ADR-0004 对还原的裁决；不做模型切换器实测（PR1 已做）。

#### 依赖与 owner

依赖：PR1（消费模型切换器实测回执）、PR3（统一判定与 stopping 定型后再接侧栏）。owner：Claude Code。
