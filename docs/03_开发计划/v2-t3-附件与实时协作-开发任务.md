# SuDuo V2 T3 附件与实时协作开发任务

> 一句话：把 300 MiB 受控硬盘附件安全地接通远程服务、本机 BFF、统一工作台和不可变会话材料，并用鉴权 SSE 驱动局部刷新。｜最后更新：2026-08-14（已验收）

## 一、任务概述

**目标对齐**：在 T2 已合并的统一工作台和 V2 BFF 上补附件与实时协作。浏览器仍只访问 localhost；远程服务独占附件根目录；需求会话只有在正文、附件和版本全部校验并原子发布后才能创建。

| 项 | 说明 |
|----|------|
| 交付目标 | PostgreSQL 002 附件元数据、300 MiB 流式附件服务、BFF 流代理、附件 UI、会话材料同步、鉴权 SSE 与局部刷新。 |
| 需求来源 | `docs/02_需求设计/v2-需求协作工作台-需求.md` 第 4.3 节及 R4、R10、R11。 |
| 技术来源 | `docs/03_开发计划/v2-工程实施技术设计.md` 第 4.3、6.1、7.2～7.3、9.3、14 节。 |
| 本期范围 | `requirements-service`、`@suduo/cloud-contracts`、本机 V2 BFF/材料服务、统一工作台附件交互和 SSE 刷新。 |
| 不含范围 | T4 部署切换；TAPD/旧本地需求清理；Codex runtime 改造；在线预览 HTML/SVG；持久 SSE 事件日志。 |
| 限额 | 单附件默认 314572800 字节，每需求默认最多 20 个未删除附件；允许 HTML/HTM、SVG，但只作不可信下载。 |
| 分工 | Codex 实现与验证；用户在门③体验确认前提供现有本机 PostgreSQL/服务环境。 |

## 二、任务分解

### 2.1 远程服务、契约与数据

- [x] **任务 2.1.1：冻结附件与事件契约**
  - 内容：附件 DTO 增加 SHA-256；增加下载审计动作、附件列表和 SSE 事件契约；存储键与路径不进入响应。
  - 产出：`cloud/contracts/src/*`。
  - 依赖：无。

- [x] **任务 2.1.2：新增 PostgreSQL 002 migration 与附件仓储**
  - 内容：附件元数据逻辑删除、索引和约束；上传/删除事务递增需求版本并审计；需求审计查询聚合附件动作。
  - 产出：`cloud/server/migrations/002_attachments.sql`、repository/service。
  - 依赖：任务 2.1.1。

- [x] **任务 2.1.3：实现受控硬盘存储与鉴权 SSE**
  - 内容：空间预检、multipart 流、限额/扩展名/SHA-256、fsync、同卷原子 rename、补偿和启动清理；流式下载强制 attachment/nosniff；内存事件 hub、心跳和鉴权订阅。
  - 产出：attachment storage、event hub、远程 HTTP 路由与配置。
  - 依赖：任务 2.1.2。

### 2.2 本机 BFF 与会话材料

- [x] **任务 2.2.1：附件与 SSE 固定路径流代理**
  - 内容：扩展 remote client 的长流能力；BFF 原样流转 multipart、下载和 SSE，不在内存缓冲，不向浏览器暴露 token；远端 401 清态。
  - 产出：V2 remote client、HTTP server 固定路由。
  - 依赖：任务 2.1.3。

- [x] **任务 2.2.2：附件化不可变需求快照**
  - 内容：先读取详情/清单，逐个流式下载到本机 staging 并校验大小/摘要，复验需求版本后原子发布；manifest 记录附件；失败不建会话。
  - 产出：material service、requirements service orchestration、会话简报信任边界。
  - 依赖：任务 2.2.1。

### 2.3 统一工作台

- [x] **任务 2.3.1：附件上传、列表、下载和删除交互**
  - 内容：顺序上传、XHR 进度、失败重试、删除确认、SHA-256 展示；下载直接导航流，不聚合 Blob；HTML/SVG 不提供预览。
  - 产出：Web API client、`RequirementsWorkbench` 与样式。
  - 依赖：任务 2.2.1。

- [x] **任务 2.3.2：SSE 连接状态、重连和局部刷新**
  - 内容：同源 `EventSource`、连接状态、重连后补拉；按项目/需求/评论/附件事件刷新受影响区域，保留用户正在编辑的草稿。
  - 产出：工作台实时协作状态和局部刷新逻辑。
  - 依赖：任务 2.1.3、2.2.1。

### 2.4 验证与交付

- [x] **任务 2.4.1：静态质量门**
  - 内容：执行 `pnpm build`、`pnpm typecheck`、`pnpm lint`。
  - 产出：验证结果。

- [x] **任务 2.4.2：人工端到端回归**
  - 内容：健康检查、API 上传/下载/删除/审计、路径穿越名、HTML/SVG 响应头、上传中断、300 MiB 流、会话材料摘要、SSE 鉴权/重连/局部刷新和旧能力 smoke。
  - 产出：门③回执；环境不具备项显式标未验证。

## 五、验收标准

- [x] 原始文件名不能改变远程或本机落盘路径；未提交和已删除附件不可下载。
- [x] 300 MiB 上限、每需求 20 个有效附件、扩展名 allowlist 和 SHA-256 均生效。
- [x] HTML/SVG 可上传下载，但响应强制 attachment、nosniff、二进制类型且 UI 无预览。
- [x] 上传、下载、删除均产生可按需求查看的审计，新增/删除递增需求版本。
- [x] 浏览器网络只访问 localhost；BFF 和浏览器不整包缓冲附件，token 不进入响应或 SSE。
- [x] 有附件需求创建会话后，本机 manifest、正文和附件摘要一致；任何失败不创建会话。
- [x] 未鉴权 SSE 被拒绝；断线后自动重连并补拉，另一客户端变更触发局部刷新。
- [x] `pnpm build`、`pnpm typecheck`、`pnpm lint` 通过；T3 定向回归通过。

## 六、风险与注意

| 风险 / 注意 | 影响 | 处理 |
|------|------|------|
| 文件系统与数据库无法形成单事务 | 孤儿文件或残留物理文件 | staging 不可见；提交失败补偿；逻辑删除先行；启动清理重试。 |
| 300 MiB 造成内存或磁盘压力 | BFF/浏览器 OOM、磁盘占满 | 全链路 stream、实际字节硬限额、两端空间预检、浏览器直接下载。 |
| HTML/SVG 主动内容 | XSS 或本机脚本执行 | 禁止预览、attachment、nosniff、二进制响应、材料简报降权。 |
| SSE 事件丢失 | 页面短暂陈旧 | 事件只作提示；连接成功/重连后补拉当前状态。 |
| 分仓流程限制 | 无法生成标准 zj-dev final receipt | 保留手工可审计提交、验证日志和合并 SHA，门③显式报告。 |
