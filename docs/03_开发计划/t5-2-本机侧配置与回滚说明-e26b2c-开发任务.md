## 二、任务分解

### T5-2 本机侧配置与回滚说明

#### 任务概述
在 T4 定版之后写，确保说明和清理后的最终形态一致——尤其是 `/legacy` 已经没有了、旧库不再保留、回滚只剩降版本这三件事。

按 D4，本机侧**只覆盖全新安装**，不写既有库升级路径。

#### 任务分解
1. 在本机安装/设置流程中补充：远程服务地址配置、首次注册登录、V2 本机数据目录的位置与含义。
2. 编写回滚说明：回滚 = 降到旧发布版本，本机库按新版本重建；写清 `/legacy` 已不存在、旧数据不保留。
3. 明确写出 D4 的代价：换版本后本机项目目录映射需要重新配置、需求材料快照需要重新同步。
4. 与 T4-4 的迁移链目标形态对齐，不得残留任何「升级既有库并保全历史会话」的表述。

#### 验收标准
- 按文档可在全新机器上完成一次完整安装与配置。
- 按文档可完成一次回滚演练（降版本 + 库重建）。
- **本片交付的安装/配置/回滚文档**中，无任何对 `/legacy`、TAPD 或既有库升级迁移的残留指引。此条只约束本片新写或改写的面向用户文档；`docs/03_开发计划/v2-工程实施技术设计.md` 的 T4/T5 章节与变更记录必然保留 TAPD 说明作为设计历史，不在本条范围内，也不得为满足本条去删改历史文档。

**文档质量要点**：
- 明确指出根 `.env.example` **不会被服务自动读取**，须将值放入实际启动环境，并分三种部署形态给出入口：WSL/Linux 安装器版改 `~/.config/suduo/suduo.env` 后 `systemctl --user restart suduo.service`；源码启动在 shell 中导出；Windows 安装器版直接用「V2 设置」页。这消除了「改了样例文件却不生效」的常见误解。
- 删库步骤包含 `-wal`、`-shm` 两个伴随文件。此细节关键：本机库 WAL 曾达 527 KB，只删 `.sqlite` 会导致 SQLite 自 WAL 恢复旧数据，硬失败照样触发。
- 明确禁止「修改 `schema_migrations` 或复用旧库」，堵住绕过 T4-4 硬失败的错误做法。
- 前后衔接到 T5-1 的 `cloud/server/DEPLOYMENT.md`，并要求先确认 `/v2/health` 可用。
- D4 代价三项写全：项目目录映射重配、需求材料快照重同步、重新登录远程服务。
