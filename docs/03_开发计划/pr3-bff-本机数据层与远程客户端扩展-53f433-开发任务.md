## 二、任务分解

### PR3 · BFF 本机数据层与远程客户端扩展

#### 任务概述
工作台要跨项目汇总，但本机这几个仓储**全都是按项目或按单个会话查的**——ref 只有 `getBySessionId` 和 `listByRemoteProjectId`，会话只有 `listByProject`，待审批只能逐会话计数。直接拿现有方法拼，就会退化成「循环里查 N 次」。

这一片只补能力，不接路由、不写聚合逻辑。**交付物是可以被注入的仓储方法与纯函数**，PR4 再把它们组装成端点。这么分是因为这些查询各有独立的正确性风险（尤其批量运行态归约），值得单独验证，而不是混在聚合逻辑里一起调试。

#### 任务分解

**1. `requirement-session-ref-repository.ts`** — 新增 `listAll()`，跨项目取全部 ref。

**2. `approval-repository.ts`** — 新增 `countPendingGroupedBySession()`，SQL 层 `GROUP BY session_id` 直接出计数。

  **不要复用已有的 `listPendingOrDeciding()` 再在内存分组**：它返回完整审批记录，为了拿几个数字搬运整行数据是浪费。注意现有部分索引是 `idx_approvals_pending(status, requested_at)`，确认新查询能命中它，命不中就说明还需要调整索引——如需加索引请在回执里说明理由。

**3. `session-repository.ts`** — 新增跨项目按 `last_activity_at DESC` 的列表查询，支持 limit。

**4. `event-repository.ts`** — 新增按**会话 id 集合**一次取回合事件的批量查询，配合一个纯函数把事件归约成运行态（运行中 / 上一回合失败 / 空闲）。

  这是本片最重要的正确性点。现有 `SessionRunStatusService` 内部的 `listRunningTurnRefs` 会扫单个会话的**全部**回合事件，全局用等于扫 N 遍。新归约必须与它在同一份数据下**输出完全一致**。

**5. 映射预检抽取** — 把 `requirements-v2-service.ts:541` 的 `verifyWorkspaceMappingPath` 抽成一个窄的 verifier 模块，让**旧的 `listMappings({verify:true})` 与新工作台共同调用同一份实现**。

  - 它是文件级未导出函数，不是类私有成员，抽出安全，且不触及 `requireValidatedLocalProject` 的创建会话链路
  - **禁止复制一份实现**——两份逻辑迟早会漂移
  - **禁止改用 `requireValidatedLocalProject`**——它遇到失效映射直接抛 409，会拖垮整页
  - R/W/X 判定与消息文本原样保留，不许"顺手优化"

**6. `remote-client.ts`** — 新增 `getProjectStats`、`listRequirementsByIds`（≤100 分批，由调用方决定并发），并让既有 `listAudit` 支持透传 `projectId`。

#### 验收标准
- [ ] 批量运行态归约与逐会话 `SessionRunStatusService` 在同一数据下输出一致——**直接对比两种实现的返回值**，不是各测各的
- [ ] 归约覆盖三种态：运行中、上一回合 failed、空闲；以及会话无任何事件的情况
- [ ] `countPendingGroupedBySession()` 结果与逐会话 `countPendingBySession()` 求和一致；确认查询计划命中 `idx_approvals_pending`
- [ ] `listAll()` 与跨项目会话列表在多项目数据下返回完整且排序正确
- [ ] 抽取后 `listMappings({verify:true})` 的既有行为零变化（原有测试全绿，R/W/X 判定与文案不变）
- [ ] `listRequirementsByIds` 分批逻辑：101 个 id 分两批；某批失败时抛出而不是静默返回半份

#### 边界
- **不碰 `http-server.ts`**——路由注册是 PR4 的事
- **不碰 `server-application.ts`**——DI 装配是 PR4 的事
- 不写 `my-workbench-service.ts`，不做跨库聚合与降级
- 不改会话运行时、审批链路、`EventBroker`
- 不改前端

#### 依赖
- **PR2**。`remote-client` 的两个新方法要对着 PR2 已定的端点与契约类型写
