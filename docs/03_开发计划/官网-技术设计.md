# SuDuo 官网 技术设计

> 一句话：新仓库 `Im-Sue/suduo-website`，用 Astro 生成纯静态站点；文案是中英两份 Markdown，构建时检查两种语言一一对应；视觉严格按已定的「接力 S」方案；截图在本机演示环境里按中英两套数据拍。｜最后更新：2026-10-04
>
> **无独立 status** —— 跟随[官网需求](../02_需求设计/官网-需求.md)。

## 一、设计概述

**目标对齐**：做一个中英对应、首屏讲清定位的产品官网。访客能在首屏十秒内看懂 SuDuo 解决什么问题；工程师两次点击内找到部署文档与 GitHub。站点是纯静态文件，没有后台、账号、表单与统计，可以放在任何静态托管或 CDN 上。改文案只改 Markdown，不动页面代码。

| 项 | 说明 |
|----|------|
| 名称 | SuDuo 官网（`suduo-website`） |
| 核心职责 | 产品介绍、工作原理、私有部署摘要、商用授权说明、更新日志、关于；中英两份 |
| 设计原则 | 纯静态；内容与代码分离；两种语言同形（缺一种就构建失败）；视觉只用品牌方案里的颜色、字体、图形 |
| 需求来源 | [官网需求](../02_需求设计/官网-需求.md)；视觉：[品牌标志与视觉方案（画布）](https://claude.ai/artifact/CaXGurbSRLXdWkJNRsC2aU) |
| 覆盖范围 | 仓库、站点、内容、截图、分享卡片、构建检查、CI、上线清单 |
| 不覆盖 | 域名购买、备案、托管开通（给清单，由用户操作）；博客、文档站、在线表单、统计 |

## 二、方案与架构

```
suduo-website/
├─ src/
│  ├─ content/
│  │  ├─ pages/{zh,en}/*.md        各页文案（frontmatter：title / description / 区块数据）
│  │  └─ changelog/{zh,en}.md      更新日志（从主仓库 CHANGELOG 同步）
│  ├─ i18n/ui.ts                   导航、页脚、按钮等界面字（中文是样板，英文 satisfies 同形）
│  ├─ components/                  Nav / Footer / Hero / TwoEnds（两端一桥示意）/ Feature / Screenshot / LangSwitch …
│  ├─ layouts/Base.astro           <html lang>、hreflang、OG、主题色、字体
│  ├─ pages/
│  │  ├─ index.astro  features.astro  how-it-works.astro  self-hosting.astro
│  │  │  commercial.astro  changelog.astro  about.astro  404.astro      ← 中文（/）
│  │  └─ en/ 同名页面                                                      ← 英文（/en/）
│  └─ styles/tokens.css            品牌色板（亮 / 暗）、字号阶梯、圆角、阴影
├─ public/                         标志 SVG、favicon、分享卡片 PNG、截图（zh / en 两套）
├─ scripts/
│  ├─ check-content.mjs            中英页面与键一一对应；禁用词（「开源」「open source」、价格、隶属说法）
│  ├─ og-cards.mjs                 用 Playwright 把分享卡片模板渲染成 PNG（中英各一套）
│  └─ demo/                        演示数据播种脚本（英文一套）与截图脚本
└─ .github/workflows/ci.yml        安装 → 检查 → 构建 → 链接检查
```

| 关键原则 | 说明 |
|----------|------|
| 纯静态 | `astro build` 产出 `dist/`，没有服务端运行时；国内、海外托管随时可接 |
| 内容与代码分离 | 文案、区块数据都在 `src/content`；页面组件只负责排版 |
| 两种语言同形 | 每个中文页面必须有英文页面，frontmatter 的键一致；界面字典英文 `satisfies` 中文；构建前检查失败即退出（需求 R1） |
| 视觉只用品牌方案 | 颜色、字体、圆角、阴影、点阵底纹、交接虚线都来自画布；不引入方案以外的颜色与字体 |

**与现有系统的关系**：

| 涉及 | 本设计如何动它 | 不动什么 |
|------|----------------|----------|
| 主仓库 `suduo-workbench` | 只读：链接到它的 README、部署文档、许可文件；更新日志从它的 `CHANGELOG*.md` 同步 | 不改主仓库代码 |
| 品牌画布 | 只读：取标志路径、色值、字号阶梯、首屏布局 | 不改画布 |
| README 演示环境 | 拍截图时启动，拍完停；英文数据另建一份数据目录 | 不动用户的联调栈 |

## 三、关键决策与取舍

- **站点生成器**：选 Astro。原因：默认输出零 JavaScript 的静态 HTML（性能指标容易达标），Markdown 内容集合与 i18n 路由是内置能力，组件写法接近 HTML。没选 Next.js 静态导出（运行时与打包体积都偏重）、VitePress / Docusaurus（文档站形态，不适合营销页的自由排版）、纯手写 HTML（两种语言同形与检查都要自己造）。
- **字体**：IBM Plex Sans、JetBrains Mono、思源黑体（Noto Sans SC）都用自托管的 `@fontsource` 包。思源黑体的 fontsource 版本已按 Unicode 区段切成一百多份 woff2，浏览器只下载页面实际用到的那几份，等效于子集化（需求风险表「字体过大」）；拉丁字只加载 400 / 500 / 600。不用 Google Fonts 外链（国内访问不稳）。
- **语言路由**：中文在 `/`，英文在 `/en/`，页面一一对应；右上角切换停在对应页面。首次访问不按浏览器语言跳转（避免搜索引擎收录错乱），浏览器语言是英文时在中文页顶部给一条可关闭的「Switch to English」提示（几行内联脚本，关闭状态存 localStorage）。
- **主题**：亮 / 暗两套色板，跟随系统（`prefers-color-scheme`），不做手动切换（需求只要求跟随系统，少一个控件、少一段脚本）。
- **分享卡片**：中英各一套 1200×630 PNG，用 Playwright 把一个 HTML 模板渲染出来、提交进仓库；不在构建时动态生成（少一个构建依赖，构建可离线）。
- **截图**：在 README 演示环境里拍，宽 1440、2 倍像素、亮色。中文界面用现有的中文演示数据；英文界面另播种一套英文演示数据（项目、需求、评论、讨论、人名都是英文），英文页面配英文截图——英文界面配中文需求标题会让海外访客困惑。播种脚本放在官网仓库 `scripts/demo/`，通过本机服务与需求服务的公开接口写入，可重跑。
- **更新日志**：主仓库目前私有，构建时拉不到；用 `pnpm sync:changelog <主仓库路径>` 把 `CHANGELOG.md` / `CHANGELOG.zh-CN.md` 复制进内容目录并提交。主仓库公开后可改为构建时按发布标签拉取。
- **许可**：官网仓库的代码与文案在上线前不加许可证（私有）；上线时建议与主仓库一致用 PolyForm Noncommercial，并保留 `TRADEMARKS` 声明——由用户在上线清单里拍板。
- **托管**：域名定了再定。技术上给出三种做法的说明：Cloudflare Pages / GitHub Pages（海外）、阿里云 OSS + CDN（国内，需备案）。开发阶段用本机预览，必要时把构建产物发成私有预览链接给用户看。

## 四、核心流程 / 逻辑

```
写文案 ─ src/content/pages/zh/home.md 与 en/home.md（同一套键）
构建 ─ pnpm check:content（同形 + 禁用词）→ astro check → astro build → dist/
       └ 任一语言缺页 / 缺键 / 出现禁用词 → 构建失败，列出位置
访问 ─ /（中文） /en/（英文）；<link rel="alternate" hreflang> 互指；sitemap 含两种语言
切换 ─ 导航右上角「中 / EN」→ 跳到另一语言的同名页面
提示 ─ 中文页 + 浏览器语言非中文 → 顶部「Switch to English」（可关闭，不自动跳转）
```

**模拟示例**：海外工程师搜到 `https://<域名>/en/`。首屏标题 “Requirements with your team. Code on your machine.”，右侧是「两端一桥」示意（团队卡片 ← 交接虚线 → 本机 Codex 会话）。他点「Self-hosting」，看到服务端三步（准备 Ubuntu → 一条命令安装 → 打开地址注册）和「Full guide on GitHub」链接；点导航「Commercial use」，读到「Companies can start right away and register within 30 days of starting to use SuDuo. Registration is free for now.」和登记邮箱。

| 处理规则 | 说明 |
|----------|------|
| 缺译文 | 构建失败，不回退到另一语言（需求 4.3） |
| 禁用词 | 「开源」「open source」（R2，允许「源码公开 / source-available」）、价格符号与金额（R3）、「官方合作」「OpenAI 出品」「official partner」一类（R5） |
| 外链 | GitHub、许可证原文、`COMMERCIAL.md` 链到主仓库；主仓库公开前链接在 CI 里只检查格式，不检查可达 |

## 五、测试策略

- **构建检查**：`check-content.mjs`（同形、禁用词）、`astro check`（类型）、构建产物的站内链接检查（每个 `href` 指向存在的页面或锚点）。
- **视觉**：Playwright 截图首页、工作原理、商用授权三页 × 中英 × 宽 1440 / 手机 390 × 亮暗，人工比对画布的首屏三张。
- **性能 / 无障碍 / SEO**：用 Lighthouse 跑首页移动端，三项各 ≥ 90（需求 4.2）；对比度在色板选用时就按画布标注的数值（正文 ≥ 4.5:1）。
- **CI**：GitHub Actions：安装 → 内容检查 → `astro check` → 构建 → 链接检查。

## 九、迁移影响与风险

| 风险 | 影响 | 应对 |
|------|------|------|
| 英文演示数据要另起一套 | 截图工作量 | 播种脚本可重跑；先用示意图上线（需求风险表），截图后补 |
| 主仓库仍私有 | GitHub 链接点进去是 404 | 上线与主仓库公开同步；上线清单列出 |
| 「速舵」商标未检索 | 中文品牌名可能要改 | 中文品牌名集中在界面字典一处，改名只改一处 |
| 字体体积 | 首屏慢 | fontsource 分片 + `font-display: swap` + 系统字体回退 |
