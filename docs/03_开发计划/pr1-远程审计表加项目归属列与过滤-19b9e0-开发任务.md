## 二、任务分解

### PR1 · 远程审计表加项目归属列与过滤

#### 任务概述
概览页的「最近动态」和「流转量迷你图」都要按项目筛审计流水，但审计表现在**根本不知道自己属于哪个项目**——它只有 `(resource_type, resource_id)`，评论、附件、产物发布还要再跳一层才能追到项目。查询时临时 join 解析的方案已被否决：planner 可能退化成 hash join，而给它加扫描上限又会和游标分页打架，造成少页、空页甚至漏读。用户已授权直接改表结构。

这一片只做远程服务侧，不碰本机 BFF，也不碰前端。

#### 任务分解

**1. 新增 `cloud/server/migrations/005_audit_project_id.sql`**，单文件内按顺序完成：加可空列 `project_id uuid` → 回填历史 → 建索引 `(project_id, created_at DESC, id DESC)` → 置 `NOT NULL`。

回填推导规则：
- `resource_type='project'` → 取 `resource_id` 本身
- `resource_type='requirement'` → join `requirements.project_id`
- `comment` / `attachment` / `artifact_version` → 经各自的 `requirement_id` 再取

**为什么四步可以放在一个文件里**：已核实远程是 docker compose 单实例、停机替换（compose.yaml 无 replicas，端口固定映射 4100:4100），迁移随 `main.ts` 启动执行，每个 migration 文件跑在单事务内。新代码与迁移同批上线，旧实例此时已停，不存在「旧实例往新列写 NULL」的窗口。**如果实施中发现部署实际是多实例或滚动发布，立刻停下来上报**，改为 expand / write / backfill / contract 四个可独立发布的阶段。

**2. 补齐三处审计写入实现**（共 9 个调用点）：
- `collaboration-repository.ts` 的私有 `insertAudit`——覆盖 createProject / updateProject / createRequirement / updateRequirement / createComment 五个调用点
- `attachment-repository.ts`——3 个调用点
- `artifact-version-repository.ts`——1 个调用点。它还需要 `artifact-version-service.ts` 把已持有的 `LockedRequirement.projectId` 传进来；**这个文件技术设计变更清单漏列了**

**3. `/v2/audit` 加 `projectId` 过滤参数**：改 `collaboration-repository.listAudit`、`collaboration-service.ts`、`http/server.ts`，并在 `contracts/src/requirements-v2/collaboration.ts` 的 `ListAuditQuery` 加该字段。游标分页契约不变。

  **范围补正（2026-08-25，coordinator 授权）**：还必须同步改 `contracts/src/requirements-v2/schemas.ts` 的 `REQUIREMENTS_V2_SCHEMAS.listAudit`。该 schema 是 `http/server.ts:446` 的 querystring 运行时校验源且 `additionalProperties: false`；只改 `collaboration.ts` 的 TS 类型，`projectId` 会在 HTTP 层被直接拒绝，验收无法达成。本补正不扩大功能范围——它是「/v2/audit 支持按项目过滤」这一既定目标的必需实现路径。**注意 `schemas.ts` 也是 PR2 的共享文件**（PR2 要加 stats 与批量 requirements 的 schema），串行执行下无冲突。

#### 验收标准
- [ ] 迁移在真实 PostgreSQL 上跑通，回填后每条审计的 `project_id` 与 join 推导结果**逐条一致**（写集成测试比对，不是抽查）
- [ ] 五种 `resource_type` 各造一条新审计，`project_id` 均正确写入——**只测端点不算通过**
- [ ] `GET /v2/audit?projectId=` 返回结果全部属于该项目；不传该参数时行为与改动前完全一致
- [ ] 游标分页在带 `projectId` 时翻页无重复、无遗漏
- [ ] 回滚可行，且**回滚顺序写进任务回执**：必须先把应用回退到不写 `project_id` 的旧版本，再执行 `DROP COLUMN project_id`——反过来做，新应用的审计写入会全部失败。回滚后既有数据与查询不受影响

#### 边界
- 不碰本机 BFF——`/api/v2/audit` 的 `projectId` 透传属 PR4
- 不新增 stats 或批量取需求端点（属 PR2）
- 不改现有端点语义、认证方式、游标分页契约
- 不改前端
