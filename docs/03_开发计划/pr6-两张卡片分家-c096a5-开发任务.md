## 二、任务分解

### PR6 · 两张卡片分家

#### 任务概述

输入框上方那两张常驻卡片（需求附件 / 需求评论）承载的能力是真的——附件要经你确认才拉、评论发出去删不掉——但常驻在那儿、用弱化通知的样式装按钮、满屏内部黑话、显示裸 UUID。这一片搬家不删除：一次性动作（模型给出了具体附件或评论全文）作为动作卡出现在产出它的那条 Codex 消息下方，处理完就消失；常驻材料（需求标题、基线版本、附件清单与拉取状态、发表评论入口）收进右栏「关联需求」tab。右栏被占用或折叠时，头部保留兜底入口。

协商查出一个必须先解决的问题：**评论提交后的回显（全文 + 评论标识）今天存在组件本地 state（`RequirementCommentActions.tsx:34`）**，动作卡「处理完消失」一旦卸载组件，回显就没了——直接违反 R9。所以回显状态要先搬到稳定宿主，再让卡片消失。

对应需求：4.4、R8、R9；技术设计 §四.4；上一需求 BR-6 / BR-7 保留项。

#### 任务分解

1. **回显稳定宿主**：评论 / 附件的提交结果（全文、评论标识、拉取状态）从组件本地态搬到**不随 `SessionRuntime` 卸载的宿主**——`SessionsWorkbench.tsx:271` 以 `key=sessionId` 重挂 Runtime，切会话即卸载，存在 Runtime 里满足不了「切会话再切回仍在」。宿主放在 Runtime 之上（`SessionsWorkbench` 级 context 或模块级 store），按 `sessionId` 隔离、按回合关联（PR2 已按回合存 suggestion，这里按回合存结果），在消息流里对应 assistant 消息下方持续渲染；**右栏材料区手动发表的评论**（没有对应 assistant 回合）回显在右栏材料区的「本会话已发表」列表，同一宿主存储、以 `sessionId` 关联。卡片消失、切右栏 tab、打开 Drawer、切会话再切回都不丢；「历史回放不生成动作卡」不得清除宿主里已有的提交结果。页面刷新后不保证回显（需求未要求，宿主为内存态）。
2. `client/web/src/components/Stream.tsx`：动作卡插槽，锚点 = 产出该内容的 assistant 消息（`watchedTurns` 中某回合按 `turnMeta` 终态且拿到完整正文时渲染）；历史回放的回合不进 `watchedTurns`，天然不出卡。
3. `client/web/src/components/ObservedAttachmentActions.tsx` / `RequirementCommentActions.tsx`：各拆成「动作卡」与「右栏材料」两个形态；文案人话化；显示需求标题不显示裸 UUID；observed / 基线 / 不可信输入等内部说法只保留在确认弹窗说明里。`SessionRuntime.tsx` L640-652 两处常驻挂载移除。
4. `client/web/src/components/ChangesPanel.tsx`：新增「关联需求」第三 tab（静态 testid，与 `side-tab-changes` / `side-tab-files` 同风格）；右栏被 Drawer 占用或折叠时头部保留「关联需求」入口——**验收硬条件**（否则手动兜底能力事实消失 = 静默回退上一需求已交付保证）。Drawer 占用的判断已存在，直接复用。验证方式：分别制造「右栏折叠」「右栏被 Drawer 占用」两种状态，点头部入口，断言材料区打开且手动评论 / 附件入口可操作——这两条断言纳入本片单测或 gate-c 步骤。
5. 保留不变（逐条核对）：独立确认动作、提交前逐字预览（`requirement-comment-preview`）、提交后立即回显全文与评论标识（`requirement-comment-submission`）、结果未确认时「不要直接重发」提示、整回合完成后才解析、历史回放不出卡。
6. R8：解析逻辑不变，只有用户先提出评论诉求、模型据此给出全文才触发动作卡；模型不得主动建议发评论。
7. 现有 e2e 步骤（`assistant-attachment.ts` 等）中引用的旧 testid 同步替换，保证不因搬家而红；时序问题留 PR7。`data-testid-baseline.json` 同片更新并通过 `pnpm testid:check`。

#### 验收标准

- 用户提出评论诉求 → Codex 给出全文 → 动作卡出现在那条 Codex 消息下方 → 确认提交后卡片消失、该消息下方持续显示全文与评论标识
- 提交后切右栏 tab / 打开 Drawer / 切会话再切回，回显仍在
- 右栏材料区手动发表的评论在材料区回显全文与评论标识，切会话再切回仍在
- 右栏「关联需求」tab 显示需求标题（无 UUID）、基线版本、附件清单与拉取状态、发表评论入口
- 右栏折叠 / 被 Drawer 占用时，头部入口可达并能打开材料区（两种状态各一条断言）
- 历史回放不出卡；并发两个回合各自的卡锚在各自的 assistant 消息下
- 页面上不再出现常驻在输入框上方的两张卡片
- 用 PR1 子集入口跑 `assistant-attachment`、`changes-and-diff` 通过；`pnpm testid:check` 通过

#### 边界

不做评论编辑 / 删除；不改需求详情页；右栏只承载本会话材料状态与入口，不复制需求详情；不改远程需求服务接口。

#### 依赖与 owner

依赖：PR2（`watchedTurns` / `turnMeta` / 按回合存结果）、PR5（线性顺序：共享 SessionRuntime 宿主状态与 Composer 上方布局，不并行）。owner：Claude Code。
