## 二、任务分解

### F · 审批档服务端收口

#### 任务概述

`APPROVAL_MODE_POLICIES` 的 `full` 档直接给 `sandbox: danger-full-access` + `networkAccess: true`，任何成员在会话里点一下就生效。个人 CLI 这样合理，但 SuDuo 是**团队内网协作工具**，应当有可锁定的边界。

用户 2026-08-16 拍板（U2）：**保留 `full` 档能力、默认不锁**；提供部署侧上限开关，**锁定后由服务端强制**，不能只是 UI 置灰——UI 置灰绕一下就没了。

#### 任务分解

1. 新增配置 `SUDUO_MAX_APPROVAL_MODE`（`ask`｜`auto`｜`full`），**未设即不锁**，行为与现状完全一致。
2. 实现单一收口函数 `effectiveApprovalMode(session) = min(session.approvalMode, cap)`。
3. `session-service.ts`：创建会话时 cap 生效期存**允许的最高档**，不存 `full`；`PATCH approvalMode` 超限返回 409。
4. 取策略点全部改调 `effectiveApprovalMode`，不再直接索引 `APPROVAL_MODE_POLICIES[session.approvalMode]`——`runtime-supervisor.ts` 三处（:31/:91/:150）、`message-service.ts` 一处（:124）。
5. 存量已是 `full` 的会话**保留原值**，运行时 clamp；解除 cap 后自动恢复。
6. `client/contracts`、`cloud/contracts` 的 `SettingsDto` 增 `maxApprovalMode?` 与 `approvalModeLocked` 两个可选字段，对齐既有 `globalSkillsLocked` 范式。只追加类型，不改既有类型。

#### 验收标准

本片的验收**必须自己闭环**，不能寄望于后面的界面片（Codex 明确指出这里最容易两边都没验）：

- 设 `SUDUO_MAX_APPROVAL_MODE=auto` 后：创建会话存 `auto` 而非 `full`；`PATCH` 到 `full` 返回 409。
- 存量 `full` 会话在 cap 生效期间**运行时被 clamp**（实际下发的 security policy 是 `auto` 档），且会话记录里原值未被改写。
- 解除 cap 后该会话自动恢复 `full` 行为。
- 未设该变量时，四个取策略点行为与改造前逐一一致（回归）。
- `SettingsDto` 两个字段可被 `/api/v1/settings` 正确返回。
- server 侧 vitest 覆盖上述全部分支。

#### 边界

- **UI 置灰不在本片**：会话头 `ApprovalModeSwitcher` 的禁用归 pr8，设置页组 5 的锁定态与 Switch 归 pr9。本片只保证「即使 UI 没拦住，服务端也拦得住」。
- 不改 `APPROVAL_MODE_POLICIES` 三档各自的策略内容，只改「允许选哪一档」。
- 不动审批链路与运行时协议（R7）。

#### 依赖

无。可与 pr1/pr2/pr3 并行。**并行安全性已复核**：本片只改服务层（`session-service.ts`／`runtime-supervisor.ts`／`message-service.ts`）与 `client/contracts`、`cloud/contracts` 的**纯追加**字段，不写 `http-server.ts` 与 `server-application.ts`，因此**刻意不进后端中央装配串行链**——pr8／pr9 都等它的契约字段，把它串到链尾会让整条前端线空等。

### 收口实现核验

`approval-mode-cap.ts` 34 行，两个导出：

- `maxApprovalMode(env)`：未配置或空串 → `null`（不锁，行为等同现状）；非法值**显式抛错**而非静默放开——fail-closed，方向正确。
- `effectiveApprovalMode(session, env)`：按 `ask<auto<full` 秩比较，`cap === null` 或未超限则原样返回，否则返回 cap。**不落库改写**。

**四个取策略点已全部改完**，逐行核验 `message-service.ts:126`、`runtime-supervisor.ts:35/:97/:158` 均为 `APPROVAL_MODE_POLICIES[effectiveApprovalMode(...)]`，无一处仍按 `session.approvalMode` 直接索引。
