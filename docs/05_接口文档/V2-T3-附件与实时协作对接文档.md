# SuDuo V2 T3 附件与实时协作对接文档

> 对接契约：浏览器只调用本机 BFF；BFF 以服务端保存的 Bearer Token 调用 requirements-service。最后更新：2026-08-14。

## 一、业务流程

```text
浏览器 ──同源 /api/v2/*──▶ 本机 BFF ──Bearer /v2/*──▶ requirements-service
   │                          │                              │
   ├─ multipart / 下载流 ────┼────────不缓冲───────────────▶│ 受控附件根
   └─ EventSource ◀──────────┴────────SSE 转发──────────────│
```

## 二、公共调用约定

| 项 | requirements-service | 本机 BFF |
|----|----------------------|----------|
| Base URL | `http://127.0.0.1:4100`（本机联调；部署地址待 T4） | `http://127.0.0.1:8787` |
| 前缀 | `/v2` | `/api/v2` |
| 认证 | `Authorization: Bearer <accessToken>` | 浏览器同源调用；BFF 从本机设置读取 Token，不接收浏览器 Token |
| JSON 成功 | 直接返回 DTO；上传 201、删除 204 | 保持远端状态码与 DTO |
| JSON 错误 | `{"error":{"code":"...","message":"...","requestId":"...","details":{}}}` | 远端错误透传；本机配置错误使用同一结构 |

附件对象字段：`id`、`requirementId`、`fileName`、`contentType`、`sizeBytes`、`sha256`、`uploadedBy{id,displayName}`、`createdAt`。任何响应均不暴露 `storageKey` 或绝对路径。

## 三、接口范围总表

| 方法 | requirements-service 路径 | 浏览器/BFF 路径 | 用途 | 认证 |
|------|---------------------------|-----------------|------|------|
| GET | `/v2/requirements/:requirementId/attachments` | `/api/v2/requirements/:requirementId/attachments` | 附件列表及对应需求版本 | 登录态 |
| POST | `/v2/requirements/:requirementId/attachments` | `/api/v2/requirements/:requirementId/attachments` | 流式上传单附件 | 登录态 |
| GET | `/v2/attachments/:attachmentId/content` | `/api/v2/attachments/:attachmentId/content` | 流式下载并审计 | 登录态 |
| DELETE | `/v2/attachments/:attachmentId/content` | `/api/v2/attachments/:attachmentId/content` | 逻辑删除附件 | 登录态 |
| GET | `/v2/events` | `/api/v2/events` | 鉴权 SSE 协作事件 | 登录态 |

与门②冻结范围一致，无新增端点。既有项目、需求、评论写接口的响应契约不变，仅在成功提交后发布 SSE 提示。

## 四、逐端点契约

### 4.1 查询附件

```http
GET /api/v2/requirements/{requirementId}/attachments
```

- Path：`requirementId` 为 UUID。
- 成功 200：`{"items":[AttachmentDto...],"requirementVersion":12}`。
- 404 `NOT_FOUND`：需求不存在。
- 调用方须用 `requirementVersion` 与详情 `version` 对齐；不一致时重拉，不能拼接两代数据。

### 4.2 上传附件

```http
POST /api/v2/requirements/{requirementId}/attachments
Content-Type: multipart/form-data; boundary=...
Idempotency-Key: <UUID>
X-Attachment-Size: <十进制字节数，可选但工作台必传>

--boundary
Content-Disposition: form-data; name="file"; filename="example.svg"
Content-Type: image/svg+xml

<binary stream>
--boundary--
```

- multipart 只能包含一个名为 `file` 的文件，不允许额外字段。
- 单文件硬上限 `314572800` 字节；每需求最多 20 个未删除附件。
- 扩展名：pdf/doc/docx/xls/xlsx/ppt/pptx/txt/md/csv/json/xml/png/jpg/jpeg/gif/webp/zip/html/htm/svg。
- `Idempotency-Key` 必填于 BFF；远端直连缺省时会生成 UUID。重复键仅在需求、文件名、MIME、大小与 SHA-256 全同的情况下复用结果。
- 成功 201：`AttachmentDto`。错误：400 `ATTACHMENT_INVALID`、413 `ATTACHMENT_TOO_LARGE`、409 `ATTACHMENT_INVALID`（数量或幂等冲突）、503 `DEPENDENCY_UNAVAILABLE`。

### 4.3 下载附件

```http
GET /api/v2/attachments/{attachmentId}/content
```

成功 200 响应头固定包含：

| Header | 值/语义 |
|--------|---------|
| `Content-Type` | `application/octet-stream` |
| `Content-Disposition` | `attachment`，含安全 fallback 与 UTF-8 文件名 |
| `Cache-Control` | `no-store` |
| `X-Content-Type-Options` | `nosniff` |
| `Content-Length` | 附件字节数 |
| `X-Attachment-Sha256` | 小写 64 位 SHA-256 |

响应体是流。浏览器应直接导航下载，不聚合成 Blob；HTML/SVG 不得在线预览。404 表示附件不存在或已删除；审计写入失败时下载失败而不是绕过审计。

### 4.4 删除附件

```http
DELETE /api/v2/attachments/{attachmentId}/content
```

- 成功 204，无响应体；先提交逻辑删除、版本和审计，再清理物理文件。
- 404：附件不存在或已删除；503：存储写所有权不可用。
- 调用方成功后并行刷新需求列表、详情附件与审计。

### 4.5 实时事件

```http
GET /api/v2/events
Accept: text/event-stream
```

连接建立后先收到 `event: ready`，随后默认 message 的 `data` 为：

```json
{
  "id": "uuid",
  "type": "attachment.changed",
  "projectId": "uuid",
  "requirementId": "uuid",
  "requirementVersion": 12,
  "occurredAt": "2026-08-14T08:00:00.000Z"
}
```

`type` 取 `project.changed`、`requirement.changed`、`comment.created`、`attachment.changed`。15 秒心跳；Token 到期由远端断流。事件是刷新提示，不是事实日志；断线后指数退避重连，连接成功必须补拉当前状态。

## 五、错误与调用方处理

| HTTP / code | 含义 | 调用方处理 |
|-------------|------|------------|
| 400 `ATTACHMENT_INVALID` | multipart、扩展名、文件名、大小声明或幂等键无效 | 展示错误；用户修正后再传 |
| 401 `AUTH_REQUIRED/AUTH_INVALID` | 远端 Token 缺失、无效或到期 | BFF 清远端会话；回设置页重新登录 |
| 404 `NOT_FOUND` | 需求/附件不存在或附件已删除 | 刷新当前需求，停止重试原 ID |
| 409 `ATTACHMENT_INVALID` | 数量上限或幂等内容冲突 | 刷新附件列表；新上传使用新 UUID |
| 413 `ATTACHMENT_TOO_LARGE` | 实际流超过 300 MiB | 禁止重试同一文件 |
| 503 `DEPENDENCY_UNAVAILABLE` | 远端、磁盘或附件写所有权不可用 | 保留草稿/失败任务，退避重试 |

## 六、字段映射与验收

| 后端字段 | 工作台字段 | 规则 |
|----------|------------|------|
| `fileName` | 附件名称 | 只展示，不参与落盘路径 |
| `sizeBytes` | 文件大小 | 字节转人类可读格式 |
| `sha256` | 摘要 | 完整显示，材料同步逐字节复验 |
| `requirementVersion` | 详情一致性代次 | 与详情版本不同则有限重试/全量补拉 |
| SSE `type` | 局部刷新类型 | 项目/需求/评论/附件分别刷新受影响区域 |
